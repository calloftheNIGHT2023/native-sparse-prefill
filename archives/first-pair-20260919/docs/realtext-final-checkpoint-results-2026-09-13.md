# 真实文本与词预测验证：均匀抽查仍未显示可靠收益

本报告覆盖成熟 Pythia 70M 检查点的冻结轨迹诊断与单层干预。后续早期检查点另行记录。当前不能以这批结果支持付费原生稀疏训练，也不能据此否定所有 QSA 训练设置。

## 具体设置

使用 [EleutherAI 的 Pythia 70M deduped](https://huggingface.co/EleutherAI/pythia-70m-deduped)，参数量实际读取为 70,426,624；从 [WikiText](https://huggingface.co/datasets/Salesforce/wikitext) 官方 train、validation、test 各取 24、8、16 个段落，每段 256 个输入 token 加下一个目标 token。同一段不跨文档拼接；所取完整文本哈希和 token 前缀哈希在这些划分间无重复。预训练数据可能包含 Wikipedia，不能称为对底座完成了训练数据去污染。

模型 commit：`e93a9faa9c77e5d09219f6c868bfc7a1bd65593c`。数据 commit：`b08601e04326c79dfdd32d625aee71d232d685c3`，配置 `wikitext-2-raw-v1`。只运行公开权重与库内 GPT-NeoX 实现，不执行仓库自定义代码。

预先固定第 2、5 层（代码索引 1、4），从每段提取实际注意力输入、旋转位置编码后的 Q/K 和 V。重建的注意力与原生 forward 输出在全部 48 段的两个层上最大绝对误差为 0；新增缓存计算检查也与逐 query 参考实现一致。目前共 10 项正确性检查通过。

每个索引器：输入 512 维、2 个 32 维 query 头、一个共享 key 头、16 维部分 RoPE、每 4 tokens 一块、选 8 块、抽查 2 块。与完整 QSA 模型相比，这只是一个缩小的外接索引器，没有 GDN 混合主干、联合训练或高效 GPU kernel。

五组对照：仅选中监督、集合外抽查、索引器全量预热、始终全量监督、仅选中监督但多训练到匹配抽查的候选评分预算。每层 3 个种子，全部方法使用同一配对初始化与数据顺序。

## 先发现并处理了参照异常

v0 使用学习率 1e-3、120 次更新。第 2 层全监督的 3 个种子均出现全部可见索引分数为零，梯度也归零。因此未把“抽查优于该全监督参照”视为方法效果。

随后冻结 v1 检查：所有方法统一使用 1e-4、1,200 次更新；预热从 12 步变为 120 步；匹配候选评分预算的原方法运行 1,462 步。没有对候选单独调参，也没有删除失效或阴性结果。参照恢复了学习，但此轮复用了已查看过的留出集，只能视为探索性优化检查。

## v1 结果

相对注意力输出误差以原模型真实 V 聚合结果为参照，统计每段后 128 个位置的平方误差与原输出平方和之比；下表为 3 个索引器种子的均值，越低越好。

| 方法 | 第2层输出误差 | 第5层输出误差 |
|---|---:|---:|
| 仅选中监督 | 0.10338 | 0.42980 |
| 集合外抽查 | 0.10298 | 0.43129 |
| 全量预热后选中监督 | 0.10507 | 0.42691 |
| 始终全量监督 | 0.11324 | 0.39766 |
| 原监督多训练，匹配候选评分预算 | 0.10134 | 0.41783 |

抽查相对普通原监督：第 2 层误差降低约 0.38%，第 5 层反而增加约 0.35%；两层均未做到 3 个配对种子方向一致。对匹配候选评分预算的原监督，两层误差分别高约 1.62% 和 3.22%。预先写定的后续验证门槛未通过。

这里匹配的是逻辑候选 query-token 评分数，不含所有索引投影、反向与系统成本；程序仍用稠密 CPU 运算。不能把这个对照称为已经完成 GPU 同成本比较或训练加速测试。

## 放回模型，是否改善真实词预测

对每个保存的索引器，仅替换它对应的一层注意力，其他层及全部底座参数保持冻结。对 16 段相同留出文本计算后半段的 next-token NLL；每个条件有 16 次 forward，共 36 个条件、576 次模型 forward，含稠密重建、教师选块和 sink+recent 参照。所有方法都评测，不按 NLL 挑选检查点。

两层稠密重建均与原先缓存的稠密 NLL 相同。原稠密模型的均值为 4.22840 nats。下表为稀疏干预后的 NLL 增量，越低越好；不是训练后的模型性能。

| 方法 | 仅改第2层的 NLL 增量 | 仅改第5层的 NLL 增量 |
|---|---:|---:|
| 仅选中监督 | +0.03220 | +0.02383 |
| 集合外抽查 | +0.03215 | +0.03133 |
| 全量预热后选中监督 | +0.03232 | +0.03601 |
| 始终全量监督 | +0.03904 | +0.02345 |
| 原监督多训练 | +0.03266 | +0.02033 |

抽查在第 2 层几乎与原方案相同，在第 5 层更差；没有出现一致的实际预测收益。16 段文本与 3 个索引器种子规模很小，不能把细微均值差异解释为显著结论。这个 NLL 是同一留出数据上的第二读出，不是独立复现。

## 研究结论的边界

这批证据不支持“均匀抽查在成熟小模型的冻结轨迹上稳定更好”。原题关心训练早期，因此下一项已固定为公开 step1000 与 step10000 检查点的同配置验证；所有设置沿用 v1，不在成熟模型结果上扫参数。即使早期出现信号，也还需要新数据确认、原生联合训练和具体贡献查重。
