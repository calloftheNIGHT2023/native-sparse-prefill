# D/E 首次对照：先测差距，再决定是否需要修复

本协议只安排随机初始化、全参数的 D（global 层密集）与 E（global 层从第 0 步开始 QSA）。它是首轮单种子筛查的配置草案；JSON 中 `launch_allowed=false`。GPU 数值检查、真实预算和连接尚未完成，不能据此启动长训练。

2026-09-17 审稿修订：按 `docs/babylm-reviewer-verdict-2026-09-17.md`，本协议仅是有界先导，不是足以投稿的证据计划，也不触发默认12条训练轨迹。阶段快照、梯度日志及位置诊断详见 `docs/babylm-pilot-observability-2026-09-17.md`。科学方案判断由助手承担。

## 对照回答什么

固定小型 GDN/QSA 混合架构、共同主干初始化、窗口顺序、损失位置及主干优化配方，比较两条语言学习轨迹。D 主干 95,391,000 参数；E 额外包含 1,475,328 个随机初始化索引器参数，总数 96,866,328。两组共同主干都更新全部参数。E 的索引器与自身稀疏核心选中支持上的 detached teacher 同时学习，不使用预训练模型、LoRA 或密集预热。

本次比较的是已公开写明的 QSA 参考训练配方。单个配方下 E 更差，不能直接证明所有 step-zero 稀疏训练均不成立，也不能排除索引器配方或实现效率的影响。

## 固定输入与暴露

- 训练集和 train-only 16K BPE 沿用已校验版本。窗口最长 2048，文件与显式标记处重置，保留尾窗，不把未知上游拼接当作可靠文档边界。
- D/E 共享 `SeedSequence([data_order_seed, epoch])` 产生的逐轮排列。每个窗口单独前向，GDN 状态、卷积与位置重置；16 个窗口累积一次更新，各窗 CE/aux 按实际有效目标 token 加权。
- 每组硬词暴露上限 100,000,000。跨窗口切开的词在每个被接触窗口分别计数；一轮为 10,001,709 词暴露。下一个完整窗口超预算就停止，不跳过它寻找更短窗口，也不截短窗口。
- 输入 token、有效 loss token、词暴露、训练更新、评测前向、失败分别记录。此设计是受限数据的 BabyLM 实验，约 1.63 亿重复暴露 token 不代表 1.63 亿不同 token，不宣称计算最优，也不能用 scaling law 外推大模型。

按下述固定种子与每更新 16 窗完成了无模型账目模拟：每组预计 225,946 窗、99,998,882 词暴露、163,224,857 输入 token、162,998,911 loss token、14,122 次更新，最后一批 10 窗。剩余 1,118 词容不下顺序中的下一窗 1,409 词，因此停止而不跳窗。证据为 `results/babylm-de-data-budget-simulation-v0.json`；这些是待执行计数，不是已训练结果。

## 首轮优化器候选值

这是一套明确的起点，不声称已经搜索到最佳超参数。两组主干峰值 LR `3e-4`，E 索引器 LR `1e-3`；AdamW `betas=(0.9,0.95), eps=1e-8, weight_decay=0.1`，梯度范数上限 1，E 辅助损失权重 1。共同主干按累计训练词数计时，前 1M 词线性升温，再余弦衰减至峰值的 0.1，终点是 100M 词。普通 LR 升温期间 E 仍使用稀疏 attention。

随机种子：共同主干 20260917，独立索引器 20260918，数据顺序 20260919。首轮不挑种子，不因一组早期较差而单方面延长训练。每次更新前先确定整批实际词数，再用该批末累计词数确定 LR；这一定义须两组一致。具体执行语义以版本化训练代码和 JSON 为准。

先用 float32 参考实现验证 GPU 正确性和可承受成本；改变精度须重新数值检查并形成新的冻结配置，不能在同一条轨迹中静默改动。参考实现仍计算完整注意力/索引器分数，耗时仅为这次作业的实际支出，不能用来宣称稀疏加速。

## 评测与解释

完整开发集共 18,792 窗口，17,418,742 个 next-token 目标。固定快速面板每源最多 8 个窗口，按 `SHA256('babylm-dev-panel-v0|source|start|end')` 从小到大选取，共 48 窗、77,707 个目标；选取不看模型结果。

快速面板只用于观察过程、发现发散和决定下一项诊断，不是最终独立质量证据。记录初始分数、每 250 次更新和训练结束的面板 NLL；D/E 在相同更新及实际词暴露处比较。完整开发集与固定 BabyLM 语言评测在训练后单独安排并记费用；最终 test 尚未读取，不能拿过程面板当最终测试。

主指标使用纯 LM NLL 的 `E - D`，不把索引器辅助损失计入 NLL。保留各源 NLL、全曲线和所有失败。单种子是探索性结果；不能把一次早期下降速度、某个有利 checkpoint 或不显著的差异写成稳定 gap/非劣等价结论。若差距稳定出现，先验证实现与配方公平，再研究原因；若接近，继续确认质量和真实成本，不人为制造修复问题。

位置诊断复用这些评测forward，在固定历史长度桶与窗口长度桶归约逐token CE，不新增模型forward。过程面板偏长窗；完整dev仍是独立计费的必要报告，不能用面板取代它。预计14,122更新时，每组过程评测58次（初始+56次间隔+最终），即2,784个评测forward、4,507,006个有效目标；再加完整dev18,792个forward、17,418,742个目标，两组合计仅这两类评测就有43,851,496个目标。它们不增加训练词暴露，但增加算力与租用时间；官方语言任务、阶段诊断和失败重做尚须另计。以上仍为未执行计划数。

## GPU 开工的最短步骤

1. CPU 训练入口和 dev 评测通过后，打包代码、tokenizer、训练/开发窗口与哈希。旧 LoRA 队列保持关闭。
2. 取得当前可用连接和实际小时价，核对已支出/余额。先仅做 D/E 各最多 12 次更新的 GPU 工程试跑，单运行软上限 1800 秒；两组连同环境准备累计上限暂定 10 美元。此金额是新批次上限，不增加历史总预算，也不是实际价格预测。
3. 独立外部进程执行整批硬超时，计入准备、空闲、验证、故障等实际租用时间。Python 更新边界的软超时不能替代它。若单步超时/显存不足，保存失败，不自动缩模型或缩窗口混入同一结果。
4. GPU 最小配置检查全支持 D/E 对齐、稀疏梯度有限、共享初始权重、断点重放，再量候选配置完整更新时间和峰值显存。工程试跑权重不能续成科学训练起点；正式 D/E 都重新随机初始化。
5. 依据两组实测速度，估算完整 100M 词轨迹、评测和失败余量。如果两组都能在核实的预算内完成才冻结并开始；否则先改实验规模并重写协议，不中途只保留便宜/成绩好的组。

有界质量先导不以完成最优稀疏GPU内核为前置条件。但若要进入效率论文论证，必须测合理优化dense中的可替换attention时间占比并实现真正跳过计算的稀疏路径；不能拿当前完整分数reference当作加速结果。

无新增训练的当前成本为零 GPU 费用；旧路线账单仍待核对。此处没有承诺训练完成时刻，也没有宣称科学结果已经成立。
