# 求和配置会改变短训练，但长序列反向仍需核验

2026-09-15 UTC。完成9条同起点的8步LoRA短训练，共72次优化器更新。原版只改变求和分组时，第一步梯度相对差21.34%–26.18%，8步参数改变量相对差29.55%–32.25%；原版固定配置重复、FP32池化跨配置均完全复现。本轮没有建立质量优势或独立论文贡献。

随后发现另一限制：在一份8K真实QKV上，复用同一次前向图做4次反向，Q梯度仍有2.65%–7.25%的相对差。K/V梯度相同。该差异不需要重新池化或选块就会出现，不能宣称提高池化精度就让长序列训练整体确定。具体反向根因和准确参考值尚未确认。

## 实验设置

Qwen2.5-0.5B base，固定revision 060db6499f32faf8b98477b0a26969ef7d8b9987；主干FP32，注意力QKV为BF16。24层均使用块稀疏注意力，B128、K4（含当前块）、长度2048、batch1。q/k/v/o投影加入rank8、alpha16 LoRA，共1,081,344个可训练参数；基座权重冻结。这是稠密预训练模型转稀疏后的LoRA诊断，**不是从零原生稀疏预训练**。

固定初始化seed2026091545，AdamW学习率1e-4、betas(0.9,0.999)、epsilon1e-8、无weight decay、无dropout、无梯度裁剪或重计算。每条轨迹使用相同的8个训练窗口，共16,384个目标token；9条共处理147,456个训练目标token，不能当成独立数据或9个独立随机种子。

输入取自固定版本WikiText-2 train；验证来自validation的4个独立窗口，共8192目标token。不用此前反复观察的test窗口做训练。原始行以自然换行连接，不插入人工EOS；完整流先分词再切成2048长度，tokenizer关于整个流过长的提示不表示模型实际输入超长。数据split、SHA、选窗索引和全部token已落盘。

## 修复代码及它的边界

src/flashmoba_fp32_pool.py在kernel内部将加载值升到FP32后求和，输出仍为BF16，不复制整份FP32 K。是标准精度修复，版权和BSD许可保留，不声称新算法。对保存的8K真实QKV，12种执行配置的池化值、路由和前向输出都与外部FP32池化逐位一致。

同一8K样本、K4、固定(32,4,3)，5轮交错CUDA-event计时的中位数：原版0.8237 ms，外部FP32池化0.8377 ms，内核FP32池化0.8191 ms。只覆盖注意力路由+前向，不是完整模型或训练速度；差别很小且存在轮次波动，不据此声称显著加速。

首个repair-v0在反向逐位相等断言失败，原源码与控制器补录的失败记录保留，未伪造完整运行日志。repair-v1增加同实现重复，确认两种FP32实现各自也会出现Q梯度差，故不能简单归因于修复。最后固定同一个前向图，只重复backward，仍复现差异：

这些调用均请求deterministic=True。记录的是此扩展、此GPU、此输入的现象，不证明所有FlashMoBA部署都有同样问题。未定位到具体源码错误，也没证明哪个Q梯度更准。FP32池化在本次2K短训练一致的结果仍成立，不能外推为8K及以上训练的普遍保证。修复目前通过前向核验，不能标记为完成长序列训练验证。

## 与前人重合和研究决策

[MinT v1 §4.1](https://arxiv.org/html/2605.13779v1#S4.SS1)明确讨论DSA选择集合因数值差异改变，以及训练/推理纠偏，使用IcePop式过滤而非逐个重放DSA选择。本文只核查相关章节，不称全文精读。

[Megatron-LM issue #5384](https://github.com/NVIDIA/Megatron-LM/issues/5384)于2026-06-16提出DSA/DSv4 top-k indexer replay，动机直接包含不同内核、精度和batch导致不同稀疏图。[PR #5386](https://github.com/NVIDIA/Megatron-LM/pull/5386)于06-17提交实现与梯度重放测试；本次API快照中仍open、未合并。它是公开提案/代码，不是已发表论文或已合并稳定功能，但足以否定“此前无人讨论稀疏选块数值不一致”的说法。

[Triton sum文档](https://triton-lang.org/main/python-api/generated/triton.language.sum.html)和本机安装版本源码支持先前的精度机制解释；不能将普通浮点归约或FP32路由作为原创理论。相关原始HTML、issue/PR API JSON与SHA在literature/flashmoba-training-overlap-2026-09-15。

**决策：保留“具体实现的路由与短训练稳定性”证据和修复原型，不把它单独包装成新的ML算法论文，不据此开启长训或扩大租卡。** 当前最先要解决的是长序列反向参考核验：固定实际稀疏图，针对重复差异最大的query计算独立高精度梯度，比较默认与deterministic分支，定位后再恢复8K训练。只有后续形成前人未覆盖的方法/结论及可靠质量-计算量证据，才扩大训练；不保证能补成论文。
