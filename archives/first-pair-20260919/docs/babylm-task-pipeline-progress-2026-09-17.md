# 首对 D/E 的语言任务接口：读取、逐题打分和汇总

本轮目标是把前一轮的概率打分接口接成可审计的流程，不是新增研究方法。只使用手写合成样例和CPU工程模型；不读取真正的BLiMP/EWoK题目、答案，不下载数据，不启动云端或科学训练。原先固定的训练tokenizer与训练/开发划分没有改变。

## 先导实验究竟报告什么

第一对D/E的主要比较仍是相同训练词暴露后的纯语言模型NLL，保留完整开发集、各来源和预先固定的位置桶；过程48窗面板负责观察曲线，不代替完整开发集。只有看到值得解释的现象，才选择下一项诊断。这里不增加默认多种子或新方法训练。

语言任务作为补充检查，首批拟采用固定上游脚本中分别执行的`blimp_fast`、`supplement_fast`与`ewok_fast`。这只是拟定选择规则：真实数据版本、文件清单/SHA、固定样本数量和费用尚未冻结，不能据此开始正式任务评测。三套分别汇总，不能把BLiMP与supplement的UID混在一起后将均值称为官方BLiMP成绩。

本轮支持的接口并不覆盖reading、AoA、Entity Tracking或(Super)GLUE微调，不是完整BabyLM fast/full suite。短语言任务常不直接触发当前top64/block4删边，它们测的是学习后的语言能力；不能独立证明远程路由有用或稀疏训练加速。

## 实现约定

固定上游commit为`6f825c291e2c4c78ad33b1935fd64d45f52642dc`，只使用已保存的代码。`official_task_records.py`负责BLiMP、supplement和EWoK的raw record规范化，以及评分后的逐题判断与汇总。来源路径、文件SHA、原始行号、原始行SHA与稳定record ID保留在旁路字段，不允许这些追踪字段混入官方任务分类。

BLiMP比较完整的正确/错误句子；supplement沿用官方文件stem作为UID。这个固定版本的EWoK比较同一个Target1在两个context之后的概率，并输出被选中的完整context+target句子，不是输出两边相同的Target1。没有擅自增加Target2或重新定义任务。

成绩先算每个UID内部准确率，再等权平均UID；逐题等权准确率另作诊断，二者不得混用。分类别统计和逐题原分都保留。固定temperature=1，不用任务标签选温度、检查点、种子或样本。

官方实现用`torch.randint`处理完全相等的最高分。这里使用独立CPU generator和固定seed，保存输入顺序、batch边界、每题平分候选与实际选择；同时报告仅由平分随机性造成的最小/最大/期望分数，这不是统计置信区间。对同一顺序/seed对齐官方算法，不声称能复现一个没有记录文件顺序与RNG状态的历史官方运行。

## 执行边界

`scripts/run_babylm_task_evaluation_v0.py`默认只生成计划。当前`--execute`仅允许明确标为synthetic的本机工程样例、固定小模型形状、最多1M参数、128题、64次forward和300秒更新边界软上限；CUDA、科学任务和真实测试数据执行均未开放。它不是付费评测入口，也不是跨Pod迁移已验证的工具。

从本项目model-only快照加载时，先核对外部指定的权重、sidecar、训练协议和tokenizer哈希，再用`weights_only=True`限制加载内容；验证参数名、形状、dtype、有限性、随机初始化来源及真实训练计数。源码改变或其他环境路径的迁移要单独审计，不绕过恢复限制。

每次执行使用新的输出目录和独占锁。先保存每批原分，再汇总；任务文件数量或SHA不符、空行、重复JSON键、无可打分目标、非有限数值等均明确失败，不静默跳题后报完整成绩。失败保留已完成批次、实际尝试/完成前向与输入token账目，不自动重跑整个任务。
