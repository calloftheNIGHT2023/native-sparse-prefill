# KV16 / 长度128 的受控压力测试

本计划在任何该配置的优化更新之前固定。用户授权继续推进更严格的测试。沿用现有A40、总500美元及原首阶段30美元额度；不租新卡，实际费率与历史账单未知。

## 要回答的问题

此前4个源值可被6个远端槽位一起保留。现在16对KV仍配top8（含自身与前一位置），先看完整注意力能否学会，再看两种已有稀疏训练配方和固定位置基线能否解题。这不是新的benchmark/方法/必要性定理；多层可中转信息，16>6不能单独证明必须动态检索。

数据为已冻结的data/router-pressure-kv16-v0/data.pt，SHA256 81e618abed621564c90b553462a2765d166c1a90d8c121d16a84433565189c29。10000训练、1000开发、1024测试；每序列128 tokens、16监督答案，测试16384答案，源值交换1024答案。生成器中的KV都在开头32位置，仍非分散布局/真实文本。旧config.json的Pydantic基类序列化省略了子类num_kv_pairs；本次明确使用张量数据和audit中16对KV配置，逐行核验16个键和标签，绝不按缺省字段重新生成数据。源数据和旧manifest不修改。

## 四个条件

1. dense：两层完整因果注意力，无索引器。
2. warm4_selectedkl_r16：前4轮完整主注意力及完整KL；之后top8，只有选中集合的KL。沿用已测试的MSA式token级适配。
3. ksa_additive_r16：第一步起top8；选中索引分数加到主logits，任务损失直接训练索引器，无KL教师。沿用已测试的KSA式16维适配。
4. fixed_values6：两层固定优先保留0起算的1/3/5/7/9/11六个源值位置，另含当前/前一位置；早期不足时按因果位置补齐。没有索引器或KL，主QK在这些位置上正常训练。这是知道布局的任务专用固定位置控制，不是原创方法。

主干445952参数（128宽/2层/1头）、同初始主干seed123；两个学习索引器用相同初始权重seed2026091470。相同训练顺序、batch32、AdamW主lr0.001/wd0.1、索引lr0.001/wd0、主cosine T_max100，原dropout保持；不声称不同形状的随机掩码逐步相同。

## 先验确定的开发集门槛与公共预算

先训练dense到40轮，不提前停止。若第40轮开发准确率>=99%，公共轮数T=40；否则原状态接续到80轮，公共T=80。仅看dense开发集设置公共轮数，不看测试集。若dense第80轮开发准确率仍<99%，跳过另外三项，保存完整负结果和dense测试，并暂停比较。不是宣称稀疏方法失败。

dense门槛通过后，其余三组全部从相同随机初始化训练到公共T，不因某组先到99%而提前停，也不为落后组单独加轮。测试和交换题只在所有允许的拟合结束后评估一次。最终仍要求dense测试/交换各>=99%，否则不能把当前比较当成有效通过实验。学习配方门槛为两测试各>=99%，并各距dense不超过1个百分点。

T=40且四组完成：新增50080主干更新、25040索引器更新、204800000输入tokens、25600000监督答案；T=80对应翻倍。若dense80未过开发门槛，只执行25040主干更新、0索引器更新、102400000 tokens、12800000答案。预算和更新按实际完成计数。

每组20分钟、整批90分钟上限，外层92分钟超时保护。每轮原子保存checkpoint，dense40/80节点另留不可覆盖副本。记录完整逐步损失、梯度、样本数、LR、分数规模、单步训练耗时、开发耗时、保存耗时及UTC。不同方法在同卡串行执行；任何时间数据仅是此小型参考实现的观测，不推导长上下文GPU加速。
