# D/E 训练入口与开发集接通记录

本轮仍是本机工程准备。科学预训练为 0 次、0 更新、0 训练 token；没有测到 D/E 的语言学习差距，也没有启动或重连旧云 Pod。

## 可执行入口

- `scripts/run_babylm_de_v0.py`：读取固定协议，执行 dense 或 sparse；不能通过 CLI 覆盖协议里的启动门槛。
- `src/babylm_hybrid/training.py`：共同随机初始化、独立 indexer RNG、逐轮相同数据排列、完整窗口词上限、按有效目标 token 加权、主干与索引器独立 AdamW 组和按词数计时的 LR。
- `src/babylm_hybrid/evaluation.py`：开发集纯 LM NLL；辅助损失不计入 NLL，输出总计和各源计数。初始/周期/终点评测的进度会存入 checkpoint，恢复不会重复相同评测点。

每次更新保留 UTC、窗口 ID、输入/目标 token、保守词暴露、LR、loss、稀疏支持计数和耗时。无目标窗口消耗预算但不产生梯度更新，其跳过输入单列；`forward_*` 才表示实际送入 forward 的输入。评测账目与训练账目分开。

checkpoint 保存模型、AdamW、Python/NumPy/torch RNG、epoch/游标、源代码/数据/协议哈希和日志完整前缀。恢复前验证这些信息以及运行环境；GPU 型号/计算能力/内存、CUDA、TF32 等发生变化时必须另做迁移审核。当前保留策略是最新成功 checkpoint 与全部独立失败快照，**不声称保留了每个中间 checkpoint 文件**。所有更新和失败日志保留。

## 实际验证结果

`results/babylm-training-engine-cpu-v0.json` 的 9 项检查最新结果通过，包括：

1. D/E 数据顺序与暴露计数相同，优化器参数组正确。
2. 下一窗口超词预算即停止，不跳过长窗去找能塞下的短窗。
3. 不等长窗口按有效目标加权，和独立手算 oracle 的更新最大差为 `4.656612873077393e-10`。
4. 零目标窗口不产生更新；LR 使用已声明的实际词位置。
5. 人为扰动 RNG 后从 checkpoint 恢复，与连续训练的模型、优化器、RNG 和游标逐位一致。
6. 错误配置、数据/源码/日志篡改及未通过启动门槛均被拒绝。
7. 注入异常后保留原始原因、traceback、失败快照及最近成功 checkpoint。
8. 初始/周期/终点评测计数与断点去重正确。

首轮为 8 项中的 7 项通过、1 项测试断言错误：测试假设失败快照有固定文件名，实际实现使用独立时间戳文件，快照本身存在。修正测试后仅重跑受影响项，并增加评测计数回归；原失败、两次 attempt 和每项源码版本都已保留。不是声称最后代码重新全量运行了所有旧检查。

审查中还修正了真实接口问题：评测返回计数位于 `metrics['total']`，训练器原先从顶层读取会默默记成零。已加定向测试。脚本入口的项目路径、共享读取器源码指纹、评测前预算检查与硬件变更恢复拒绝也一并补齐。

本轮训练器检查含独立 oracle 和恢复重放，共 **45 次完整 tiny-model forward、44 次 backward、24 次工程 optimizer 更新**；所有输入均为合成 fixture，不是 BabyLM 训练。dev 入口另完成 7 个 fake 模型测试及 **1 次 tiny 随机模型真实 dev 工程 forward（7 输入 token / 6 目标）**，没有 backward 或更新。

结合上一轮 26 forward / 11 backward / 5 工程更新，已登记的完整 tiny-model 工程累计为 **72 forward、55 backward、29 更新**。注意力单模块检查另列，不与科学训练混计。
