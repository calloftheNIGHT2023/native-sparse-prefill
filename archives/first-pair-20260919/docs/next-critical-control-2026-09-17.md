# 下一项必要成本对照：密集训练能否更早停下

当前匹配试验证明：在同样128次更新下，稀疏训练加QK恢复约省7.6%–7.7%的训练产物时间，并通过所用质量筛查。这仍不是达到同一质量所需总成本的证明。

必须检查一个更便宜的对照：密集训练到64步就停止，是否已经达到稀疏128步加恢复的质量。已有WikiText密集64步结果好于稀疏128步，提示这个对照有实质必要，而不是提高用户的质量要求。

待当前LAMBADA评测完成后，优先用已保存的当前4090匹配64步检查点做评测，暂不扩大训练：两个种子、密集与稀疏、各含原权重和已知QK恢复。固定评测原第二批词题、WikiText、PG19；若LAMBADA基座门槛通过，也纳入该任务。所有这些数据届时均已暴露，只用于成本曲线开发诊断。主对照预先写清密集64步对稀疏128步恢复后权重，附密集64步恢复后的对称比较。不得挑选有利指标或临时改变容差。

使用完整训练日志的前64步计时，加校准/保存/初始化的可核对开销；若只有UTC检查点事件，应明确与单调时钟实测的区别及精度，不拼接不同GPU。需要时可做一次有上限的匹配时间重测，但先利用现有信息。

如果更早结束的密集训练达到相同质量而更便宜，保留128步固定预算的省时事实，同时收窄实用性主张，不包装成同质量成本优势。如果密集早停无法保留某项能力，则继续定位哪种能力形成了真实的质量—成本权衡。

QK-Restore、稀疏训练后密集评测已有前作。上述对照属于必要基线，不是原创方法。
