# 稀疏化推理加速：基于已有实验的成果机会评估

评估日期：2026-09-14。范围：长上下文 prefill，即处理输入、生成首个 token 之前的计算；沿用原对话的范围。当前状态：选题评估完成，尚未确认新方法贡献；本轮新增训练、GPU实验、云作业均为0。

## 结论

有值得继续筛查的推理方向，但现有材料尚不能支撑一篇新的稀疏加速方法论文。优先考虑“已有模型的稀疏推理校准与实际执行效率”，暂停围绕旧小任务的训练失败继续设计修复方法。

最值得进行一次有限筛查的问题是：**在 GPU 要求多条查询共享 KV 块的条件下，能否保护被平均评分忽略的查询，在相同实际延迟下保持更好的任务质量？** 这只是待检验假设。共享支持、按块蒸馏、代表查询选择等组成部分均有前作，新颖性尚未确认。

成果分为三个层次：

| 层次 | 当前判断 | 还需要的证据 |
|---|---|---|
| 可复现技术报告、诊断工具 | 已有实质材料 | 把学习率、训练时长、路由必要性反例整理成清晰可运行的材料 |
| 推理工程成果、开源实现贡献 | 值得优先争取 | 可运行的稀疏后端、真实首字延迟收益、准确率和边界情况验证 |
| ICLR 类方法论文 | 当前证据不足 | 明确区别于前作的机制、真实模型上的强基线优势、独立数据和完整系统测量 |

“能写出实验报告”“能提出候选”“能支撑主会论文”对应不同证据要求；这里不把任何候选标成已确认创新。

## 一、另一个对话真正留下了什么

已读取任务「梳理大模型调优选题」（01a09199-b44b-75f2-a624-9c935dbb3f66）和「解释稀疏化推理加速」（01a09cd8-eedc-7f01-8e3f-ec716bede4aa）。前者最近若干轮的接口返回空 items，因此以当前落盘报告补足后续结果。以下是本轮读取的文件证据，不是本轮重新训练或独立重算的结果。

### V001：学习率反例关闭了最新训练障碍候选

同一原生 top8 配置，学习率0.01续训64轮的新题准确率为8.0200%；换成作者另一档学习率0.002154434690031882后，seed123和seed124均达到99.9939%，交换源值测试均为100%。改变学习率已经足以给出当前失败解释的反例。

来源：[最新结果报告](router-author-falsification-results-2026-09-14.md)“统一新测试结果”和“为什么撤回当前角度”；[保存的审核记录](../results/router-author-falsification-analysis-v0/audit.json)记录审核通过及202752个CPU复现答案。本轮只读取报告与审核记录，未重新执行该审核。

结论边界：这证明当前配置不需要新机制才能通过该任务；没有证明所有稀疏训练问题都解决，也没有证明低成本索引器、真实文本或真实加速。

### V002：较早的索引器差距也已由续训大幅消除

在4对KV、长度64的旧任务中，80轮时16维和64维学习索引器分别达到99.9512%和100%新题准确率。40轮的明显差距不能继续当作“联合训练学不会”的证据。

来源：[80轮结果](router-epoch80-results-2026-09-14.md)“用同一批新题比较40轮与80轮”。这与V001是不同实验设置，应分别报告。

### V003：已有高分任务包含必须排除的简单策略

保留第一层路由，仅将第二层改成固定覆盖4个源值位置，旧三组模型仍超过99%。旧任务高分不能单独证明第二层必须按问题动态筛选记录。

来源：[路由必要性诊断](router-necessity-results-2026-09-14.md)“同一批题的对照”。固定策略知道生成器布局，仅用作诊断；不能推广为任意文本上的算法。

### V004：此前两个窄改法已经关闭

均匀抽查未选块与头间归一化校正都没有稳定通过原先的收益门槛。它们可保留为负结果与诊断实现，不宜改名后重新投入。

来源：[三检查点阶段决定](realtext-all-checkpoints-decision-2026-09-13.md)、[头间校正结果](head-mixture-results-2026-09-14.md)。有关早期评分器失效的限定仍保留，阴性结论只适用于已测配置。

### 可复用资产

已有数据划分、冻结主干索引器训练、逐层干预、源值交换、轨迹保存、权重与日志审核工具。它们能降低下一轮验证成本。目前参考实现仍计算完整QK或使用稠密掩码，无法据其稀疏率推导 GPU 加速。

## 三、第一优先：共享执行约束下的稀疏路由校准

### 直观问题

逐条查询分别挑位置时，各自可能选得很好。执行时若让一组查询共享选中的块，直接取并集会扩大读取和计算；若把并集压回固定预算，又可能删掉只有少数查询需要的内容。平均注意力分数高，并不自动保证组内所有关键查询都得到足够上下文。

上述约束与前作一致；下面关于“少数查询被平均评分掩盖”的可利用程度是分析假设，尚无本项目实验支持。

### 一项具体候选

冻结已有语言模型，使用已有块稀疏后端。校准一个小索引器，使它在真实查询分组、因果边界、KV页布局下选择共享块。在训练中比较普通平均蒸馏与强调组内较大输出误差的目标；推理只运行这个索引器和既有稀疏算子。

首轮固定查询分组，避免同时加入动态分组、额外路由层和主干LoRA，导致收益来源难以识别。若训练后确实获益，再研究是否需要更复杂的支持策略。

这使用的是常见的蒸馏与尾部误差优化思想。论文贡献只能来自新的、明确的机制与实证优势，不能来自把这些组件组合起名。QUOKA代表查询、普通块蒸馏、简单增加预算是必须尝试的反例。

### 为什么比重新从零训练更适合当前基础

可以复用已有索引器校准和干预工具；训练主要限于小模块。训练算力需求预计较低，但长输入教师轨迹、数据生成与端到端评测仍会产生显著成本，需实测。小MQAR与Pythia-70M只用于代码检查，主结果应来自有可靠长上下文能力的公开预训练模型。

### 第一次筛查：先判断有没有值得修复的缺口

先固定一个公开长上下文模型与兼容后端，锁定版本。模型规模建议先在单卡可容纳的3B–8B范围选择；具体选择服从模型上下文能力、内核支持和显存预检，尚未承诺某模型能跑某长度。

第一阶段只做冻结模型诊断，建议先测8K、16K、32K，至少包括检索和证据组合两类任务。划分按文档/任务实例隔离，不能只是不同位置片段；先确认稠密模型有可靠的任务表现。全部计算遵守逐查询因果范围。

| 条件 | 回答的问题 |
|---|---|
| 优化后的完整注意力 | 任务本身能否回答、总延迟里注意力占多少 |
| 逐query精确评分选择 | 当前预算是否还有质量空间；仅为昂贵诊断参考 |
| 完全相同执行粒度下的精确评分共享选择 | 共享支持是否引入额外质量损失 |
| 普通块索引器/代表查询选择 | 便宜实现与诊断参考差多少 |
| 提高预算的原方法 | 简单多读一些内容是否就能更好地解决问题 |

“精确评分参考”不保证是下游准确率的数学上界。共享块的并集执行若额外纳入位置，须明确记录实际支持集合，不能说它与原掩码等价。

### 第二阶段才做小模块校准

仅当共享选择出现稳定损失时，比较相同初始化、数据、更新预算下的普通蒸馏和候选目标。至少三个索引器种子；独立确认集保留到方法及超参数固定后。主干先冻结，稠密教师计算与校准时间完整计入成本。

建议的内部继续门槛（未运行，也不是会议录用标准）：

1. 在至少两个长度、两类任务上，共享支持相对逐query参考存在可重复、超出样本噪声的差距；可用至少2个百分点作为首筛实际意义阈值。
2. 候选在相近实测延迟下改善至少2个百分点，或在预定质量容差内比最强适用稀疏基线缩短至少15%的完整prefill时间。二选一的主指标应在拟合前确定，不能看到测试结果后挑选。
3. 进一步报告相对优化稠密基线的完整prefill收益；短输入和轻负载的退化也保留。准确率区间按独立任务样本统计，校准种子波动单列。
4. 增加原方法预算、普通块蒸馏或代表查询选择若已经消除收益，结束该候选。

这两阶段可以安排成约1–2个工作日的首筛目标，不是已验证的工期。沿用原研究500美元总额与分阶段限制；已有账单未核实，因此不能把名义总额视为剩余额度。本报告未启动任何收费执行。

## 四、实际加速必须怎么判断

先分别测量：索引评分、top-k、KV表/收集、注意力算子、完整模型prefill。若只计稀疏乘法，可能遗漏大部分新增开销。

需要同时报告两组比较：相同逻辑稀疏预算的算法比较，以及相同实际时间/质量容差的部署比较。物理读取块数、实际参与计算位置和索引临时显存都要记录；逻辑top-k相同并不代表工作量相同。

完整prefill时间包含所有模型层和选择开销；服务TTFT还包括排队与调度，两者分开。无排队单请求先测纯实现收益，再固定请求长度/到达率测chunked prefill与混合负载。精度、batch、缓存命中、编译预热、GPU型号和稠密后端版本保持可比。运行须确认真正进入稀疏路径，掩码正确性检查通过不能替代性能剖析。

作为算术检查，若注意力只占原始prefill时间的比例f，其他部分完全不变，即便把这部分耗时降为0，理想总加速也只有1/(1-f)。例如f=0.3时约1.43倍；这是成本上界示意，不是本项目测量。

冻结模型的prefill稀疏化也不会自动减少完整KV缓存。需要区分计算临时显存与持久KV缓存，避免把跳过读取当成永久删除。

## 五、第二优先与不再投入的方向

**第二优先是明确后端/硬件下的工程优化。** 以一个已有稀疏方法为基线，定位索引、块表或分页访问的热点，提交可验证的优化实现。跨层缓存、块并集和下一层预取都有前作（V008、V011、V013）；具体代码贡献仍可能有用，但能否形成论文取决于新机制、推广范围与实测收益。当前尚未发现或验证一个这样的具体热点。

**暂不另开多跳稀疏基准作为主线。** 它适合筛查失效模式；因果链监督已有V012。仅增加记录数或加入源值交换，更适合补强评测，论文空间尚未建立。

**旧候选保持关闭。** 均匀集合外抽查、当前头间校正、单层预热以及被学习率反证的训练修复角度，都不因本报告重新打开。
