# 候选粗筛阶段：模型效果接近，prefill 效率尚不合格

更新时间 2026-09-15T02:04:47.554766+00:00。当前具体变体暂不扩大训练；本轮训练更新 0。现有 RTX 6000 Ada 足够继续小规模研究，无需新租卡。

## 得到了什么

用已知的块内 min/max 摘要，先选四个远端块，再精确选六个远端 token，加上两条局部边。在新生成的 1024 条基础题及其换值、噪声变体上，两个冻结模型默认分块共 67584 个预测，全部与 exact top-8 一致。FP32 与 BF16 各自对照均成立。

但严格的“四个分块边界都逐答案一致”门槛**未通过**。FP32 偏移 8/24 分别改变 14/5 个答案；BF16 为 14/6。所有保守配置的准确率仍很高，但不能称为普遍无损。换边界是同一输入上的路由干预，不是四份独立测试集。

min/max 融合算子比本轮 Python 原型快很多，仍未在任何本轮测试形状超过 FlashAttention。较快的均值粗选在换值题上明显失败，不能把它的速度与另一种配置的准确率拼起来。

## 质量结果与数据边界

第一步完整测了 18 档已知粗选配置，两个冻结模型，旧的三个 split：114 个含 exact 的模型评测条件。然后在新题预测前固定 9 档确认条件；每档两个模型、三个 split。再用融合 FP32 和融合 BF16 回放。总计 276 个评测条件，**不是训练轮次**。

| mean32_r4_negative_control | 4504 | 4503 | 25.2930% |

BF16 表中相对的是 BF16 exact，不能直接将该列当成与 FP32 的差异。融合 FP32 在全部 608256 个条件内预测上与 Python 确认版完全一致；融合 BF16 在全部同配置比较中与 FP32 共改变 21 个预测，逐文件统计在审计 JSON。

新数据与旧 100000 条训练、3000 条开发及多个测试文件按输入哈希排重。模型仍为约 1.2M 参数、N256 的合成 MQAR；任务的 16 对源键值位于开头，不能当成长文本或真实 LLM 结果。新题只在本轮第一次确认时属于未暴露数据，后续实现和精度回放不算又一次独立泛化。

块宽 32、选四块在 N256 下并不激进：加当前块，每个 query 的细筛候选槽上限为 160。全前缀平均保留远端候选量的保守上界为 81.05%；还要额外计算粗评分和摘要。不要把最终只聚合八条边当成只付出八条边的全部计算。

## 真实 prefill 计时

RTX 6000 Ada，torch 2.4.1+cu124，BF16 Q/K/V，B1、D128；表内为 CUDA Graph 的 GPU 毫秒中位数。所有方法都用相同计时输入，并报告 eager 对照；每项 9 轮、每轮 3 次。每次调用重建摘要、粗排序、候选精排及聚合，未免费缓存路由。Flash 后端由 profiler 核实。

32K 单头均值粗筛有小幅计时优势，但其模型质量不合格；8 头没有这个优势。min/max 在 16K/32K 比旧全量 token 评分版更快，却仍慢于 Flash。它保留 FP32 粗评分，不能把当前精度和实现开销当作所有块稀疏算法的必然下界。

工程诊断中，8K/8 头 Python 原型约 50.079ms，融合后约 2.772ms，约 18.1 倍改善。这两个早期计时批次使用不同随机抽样，作为工程量级参考；上表采用后来统一输入的 v1 主对照。随机 QKV 的 32K 计时与 N256 模型质量必须分开解释。

## 数学检查与修正

min/max 分数是块内 token 分数的上界，但上界排序不等于真实最大值排序。即使免费提供真实第六远端分数，所检查的 b32/r4 答题位置也需要保留全部已完成块才能按此上界认证不遗漏。说明当前上界太松，不能将经验上保住答案解释成精确 top-k 证书。

初版诊断计数将前一个块中的一条局部 key 多计入，某些比例略超 1；`block-candidate-diagnostic-correction-v1` 已按真正远端有效位置重新计算。原 v0 数据与源码保留。该错误不影响路由选择或模型答案评测。当前诊断 288 行，不把原版与修正版当两份独立证据。

CPU 的五项检查覆盖独立循环参照、全块恢复 exact、因果性、短序列、分块边界。融合 GPU 的 30 项覆盖 FP32/BF16/FP16、五种形状、两种粗选规则，核对候选分数、选中集合和同一支持集的前后向；全部通过。第一阶梯度检查不是训练稳定性的证明。

## 贡献筛查和决定

块均值来自 MoBA；min/max 来自 Quest；小块、信噪比、key 卷积与融合选块已有 FlashMoBA。相关原文、核查章节和限制见[本轮计划](block-candidate-plan-2026-09-15.md)。这些已知机制不能因我们重新实现就算原创。

现在可以确定：这条“min/max 粗选 + token top-8”具体实现有短序列冻结模型的质量可行性，当前 prefill 效率不合格，且没有确认的新贡献。**不把它直接扩大为付费真实文本长训或一篇论文。** 这不否定原生稀疏训练整个方向，也不要求必须超过所有新模型的准确率；同等效果下的实际优势仍然是合理目标。

下一轮的有效入口是建立官方优化过的块稀疏强基线，检查其实际训练/prefill瓶颈，再筛出超出已有路由规则的具体改动。不要继续在这个玩具任务上反复长训，也不要不断扩大随机序列只为找到一个阳性计时点。
