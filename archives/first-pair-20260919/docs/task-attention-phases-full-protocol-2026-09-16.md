# E1e后续：补齐全部旧开发题的阶段路径诊断

## 为什么改变诊断范围

首24题E1e冻结筛查失败，两个种子的SS为8/24、9/24，DS为8/24、8/24，target_D为8/24、9/24。没有通过原门槛，不将其改写为通过。

查看原正常密集训练结果后发现：同24题密集训练/密集使用为9/24、7/24，均值33.33%，而SS为35.42%。主要退步发生在剩余72题：正常密集为35/72、37/72，SS为25/72、25/72。因此仅凭前24题的负干预不足以解释完整96题上的质量差距。

这是看到失败结果后新增的诊断范围修订，不是原E1e自动通过后扩展。修订原因是检查样本是否呈现待解释现象，不挑密集对/稀疏错的题，不删除任何条件。原失败协议、预测和报告均保留。

## 此次执行

只把四个完整的前缀/后缀组合SS、DS、SD、DD补到剩余72题，两个原K16高LR断点、同一内核和加载配置。新增576次计分前向、0训练更新。与之前24题合并成全96题四格表；目标段/无关段局部条件仍只覆盖24题，不扩展也不与全96题均值混合。

这里是对既有开发题的事后诊断，不是新的独立测试。保持全部四个条件，双种子顺序反转；模型校准、原SS/DD logit、因果前缀采样哈希继续检查。只报告完整差值与配对区间，不新设通过门槛、不训练、不因此启动新题测试。

总GPU作业上限700秒，每个种子300秒。原内核预检已经通过且源码SHA相同，不重复运行预检；归档包含原预检。实际控制器读取本轮协议。所有剩余题在协议生成时一次锁定，计数72。

所有条件使用稀疏训练权重。正常密集训练结果只从原正式评测中复用并单独列为参照，不能把DD（稀疏权重密集运行）当作正常密集训练模型。混合路径依旧计算两种注意力，诊断耗时不构成加速证据。
