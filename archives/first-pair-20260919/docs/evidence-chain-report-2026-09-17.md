# 稀疏继续训练：截至2026-09-17的证据报告

本报告为密集64步控制核验后、稀疏64步控制正在运行时的快照。原始数据和后续状态以各阶段审计及STATE.md为准。

## 1. 我们到底要做什么

研究目标始终是：继续训练时用稀疏注意力减少计算，最后得到质量接近密集训练的模型，并实际节约训练时间或租卡成本。无需证明推理更快，也无需每项分数都超过密集模型。

当前实现是Qwen2.5-0.5B的32K上下文LoRA继续训练，使用已有FlashMoBA稀疏算子。训练Q/K/V/O的1,081,344个适配器参数，固定128更新、两个种子。不是Qwen4、从零预训练或全参数训练。统一按密集注意力评测，避免把训练权重变化与评测算子变化混为一谈。

有三个不同问题：同样训练步数能否省时；质量是否在预先接受的范围内；达到所需质量的最便宜训练方案是否真的使用稀疏。前两项已有积极证据，第三项正在补成本曲线。它并不是额外要求稀疏必须更强。

## 2. 目前最扎实的积极结果

同一张RTX4090、相同数据顺序、学习率、AdamW、非重入梯度检查点、相同128更新，稀疏训练结束后执行已有的QK-Restore操作。具体操作将Q/K的LoRA更新清零，保留训练得到的V/O更新。

|比较|种子2026091660|种子2026091661|
|---|---:|---:|
|密集训练产物时间|578.60秒|578.70秒|
|稀疏训练加恢复保存时间|533.85秒|534.58秒|
|省时|7.73%|7.62%|

产物时间包括模型加载、预检、训练、训练内校准、检查点和恢复保存，不含最终科研评测。单步计时也包含完整前反向、重算、AdamW等；没有拿逻辑稀疏率替代实际加速。这里报告的是单次训练过程时间，不是整个项目账单。

质量方面：第二批32K找词任务上，稀疏恢复后两种子平均91.02%，密集原权重85.94%。WikiText与PG19子集也通过事先固定的质量筛查。不能把这组开发题上的均值更高解释成普遍能力更强。

自然任务LAMBADA固定512题，稀疏恢复后47.85%，密集48.54%，差−0.68个百分点，条件95%区间约[−2.44,+1.07]个百分点，在预设最多低5个百分点的范围内。该任务最长147tokens，并不是长文本理解评测。

来源：[同卡匹配训练报告](matched-restore-training-results-2026-09-17.md)、[LAMBADA报告](lambada-natural-retry-results-2026-09-17.md)。

## 3. 外部文本结果，以及不能藏起来的损失

第一轮PG19外部评测中，恢复后的稀疏模型整体困惑度比密集约高0.93%，结尾4K目标困惑度约高1.37%，都在固定5%容差内。使用16本书的32K窗口，按书配对重采样；不是官方完整PG19榜单。

但这批继续训练模型在PG19上都不如未训练基座。因此可写“相对密集继续训练保留近似质量”，不能写“在所有外部语料上通过训练得到提升”。

Q/K恢复也不是免费提高所有能力：稀疏原权重在LAMBADA平均51.37%，恢复后降到47.85%。它改善了所测长程找词，却损失部分自然词预测收益。这是需要保留的权衡，而不是挑不同模型分别汇报各自最好的任务。

来源：[PG19报告](pg19-quality-retry-results-2026-09-17.md)、[LAMBADA报告](lambada-natural-retry-results-2026-09-17.md)。

## 4. 已否定的直接改法

把Q/K从训练开始就固定，只训练V/O，没有复现训练后恢复Q/K的效果。稀疏平均长题正确率约55.47%，密集81.25%，差−25.78个百分点，条件95%区间[−36.72,−14.84]。虽然省时约7.5%，该配方未通过质量筛查。

这说明“训练时允许Q/K变化，最后撤回”与“一开始不让Q/K变化”是不同优化路径。它是可进一步研究的现象，但目前还没有证明新的机制定理，也不能据此宣称首次发现Q/K与V/O功能差异。

来源：[固定Q/K训练报告](vo-training-results-2026-09-17.md)。

## 5. 最新控制：密集模型能否早停

不能只比较密集128步和稀疏128步，因为密集模型可能更早达到需要的质量。已保存的密集64步检查点不需要重新训练。

|条件，两种子平均|32K找词正确率|LAMBADA正确率|产物时间约|
|---|---:|---:|---:|
|密集64步，原权重|88.28%|48.63%|298秒|
|密集64步，恢复Q/K|88.67%|48.14%|298秒|
|稀疏128步，恢复Q/K|91.02%|47.85%|534秒|

密集64步比稀疏128步便宜约44%，WikiText、PG19整体与尾部、LAMBADA均通过预设比较。仅长题正确率的区间过宽，未能确认最多低5个百分点：原权重差−2.73pp，97.5%区间[−11.33,+5.47]pp；恢复后差−2.34pp，区间[−11.72,+7.03]pp。

正确解读是：目前无法排除更便宜的密集早停方案已经够用，也无法确认它的长题质量足够接近。不是“密集失败，所以稀疏胜出”。只用32个独立背景产生的128反事实题，精度有限。

当前正补稀疏64步的四个缺失评测：两个种子、原权重/恢复QK，与同卡密集64步比较相同五项质量和成本。0训练更新，预期2580条预测、244次NLL计算。统一64步双方采用日志UTC到检查点重载计时，另加恢复保存；并加1秒敏感性检查。历史128步产物为单调时钟计时，不能伪称跨步数时钟定义完全相同。

来源：[密集64步报告](dense-early64-results-2026-09-17.md)、协议`../provenance/sparse-early64-protocol-v0.json`。

## 6. 哪些是已有工作，哪些仍需建立贡献

稀疏微调、训练后密集评测不能作为全新概念，[LongLoRA](https://arxiv.org/abs/2309.12307)已覆盖相近的大方向。Q/K恢复和路由损伤分析也有[Attention Amnesia / QK-Restore](https://arxiv.org/html/2606.11052v1)。这两项都必须作为前作与基线明确署名。

新核验的[Learning how to Forget](https://arxiv.org/html/2608.19920v1)研究带KV淘汰策略的稀疏微调，利用缓存决策重放、检查点和CPU卸载控制反向内存；它并非只讨论decode。其设定与我们块稀疏继续训练后密集评测不同，但进一步限制“首次低成本稀疏微调”的宽泛主张。具体差异另见本日相关工作补充。

现在可以成立的是一个小规模实验结论：固定预算内，已有稀疏训练加已有恢复基线，在本模型与这些数据上呈现约7.7%的成本降低及可接受质量。尚未建立足以支持方法论文的原创贡献，也未证明真实成本最优。更有价值的候选问题是：训练时Q/K变化是否帮助V/O学到能力，而训练后保留这些Q/K变化又影响能力保持；但这个候选必须继续与前作区分，不能仅换术语。

## 7. 怎样往下走

先完成64/128同预算成本曲线，不增加训练。之后根据五项指标整体决定：若64步也支持接近质量和省时，冻结更大独立背景的确认评测；若更便宜密集方案已经足够，保留固定步数加速，收窄最省钱的主张；若稀疏64步不够，则定位是训练进度、恢复权衡还是区间精度，避免无目的延长训练。

独立确认必须先固定检查点、指标、容差和样本量，使用未参与选择的背景/任务，不通过多试版本挑最好成绩。未知基座预训练接触不能靠当前数据排重消除。需要更多训练种子或模型时，再按具体待验证问题设置有上限的实验。
