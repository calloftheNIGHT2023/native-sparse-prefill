# QSA：prefill 稀疏化与从零稀疏预训练的可行性

检索日期：2026-09-13。范围由用户限定为 prefill，不研究 decode 专用 KV 淘汰或压缩。这里将“全程”解释为从随机初始化预训练、继续预训练到推理 prefill 持续使用稀疏注意力。如果指整个 prompt 的 prefill，QSA 已有该用途。

## 判断

可以研究从预训练早期使用 QSA，但官方报告只验证了后期转换配方；不能推出原版 QSA 从第一步启用就能无损、更省时。原生稀疏训练已有直接前作，不能以“第一次把稀疏化用于预训练”为贡献。当前为可行性调研，无新增训练或性能实测。

## QSA 原文证据

[Qwen3.8-Next 技术报告](https://arxiv.org/html/2608.30320v1)，§2.1.2 Training Details、式18–20、Implementation Details、Fig.6：256K CPT 中，先冻结主干，用全量注意力分布训练索引器1000步；再联合训练8000步。后一阶段索引器的 KL 监督只覆盖已选择的块。默认每块4 tokens、预算2048 tokens，加未完整尾块。作用于原有全注意力层，GDN 层继续保留。原文没有给出从随机初始化全程 QSA 的对照。1M prefill 的7.6倍是含索引器的注意力模块测量，不能当整模型或训练加速。

## 为什么不能直接打开开关：分析与假设

1. 独立索引器若仅输出离散 top-k ID，语言建模损失不能通过该 ID 直接训练其排序。QSA 的 KL 提供额外监督；不能删掉预热又删掉学习信号。
2. 从零训练时，主干给出的监督本身也在快速变化。MSA 已实证研究这个问题。对 QSA 来说，早期错误选择是否导致长期遗漏，仍需测量，不能写成已确认失败。
3. 只在选中集合内计算 KL，不能直接监督集合外哪个块更好。这是计算图的观察；不等于未选块永远无梯度，共享投影和其他查询仍可改变后续排序。
4. prefill 的 forward 节省不能自动转化为训练收益：要计入 backward、索引、top-k、辅助监督、通信和额外训练步数。固定压缩率 r 时，QSA 索引仍有 O(n²/r) 的评分项；不是严格线性。
5. 短序列与 GDN 混合会压低收益。按每个查询最多看 K 个历史 token 的理想化计数，因果注意力的保留比例为 [nK-K(K-1)/2]/[n(n+1)/2]（n≥K）。n=4096、K=2048 时约75%，而非只保留50%。忽略尾块、块对齐、索引器开销，此处仅为算术说明，不是速度结果。

## 保留的具体研究问题

在 GDN 与 QSA 混合模型中，能否用低成本的监督覆盖机制替代长期稠密训练/索引器预热，并在相同总计算预算下保留长程检索能力？其中“监督覆盖机制”尚未定义为原创算法。需要继续对照 MSA、HiLS、NSA、MoBA 及索引器训练近作，不能只换成 Qwen 架构就声称贡献。

可考察的变量：主干成熟度、索引器选择覆盖、块粒度与 token 预算、辅助梯度流向、GDN/全局层比例。机制解释必须给出可证伪预测，例如预算相同下，遗漏的重要块何时仍能被重新发现，以及这是否影响远距离检索。这里尚无新定理。

## 最小验证方案草案（未启动）

先用同一小型语言模型和真实文本，固定 GDN 比例，比较：全注意力全局层；稠密预训练后 QSA；短暂稠密预热后 QSA；第一步 QSA；原生稀疏强基线。所有组用相同数据顺序、分词器和评测，并同时报告同 token 与同总 FLOPs/时间两种口径；转换前训练成本不能漏记。

测语言建模损失、末段 token 损失、多个长度的检索和证据组合任务；同时测 GPU 上 prefill 延迟及训练 forward/backward。诊断性的全量注意力抽查开销单列。保留准确开始/结束时间、失败、峰值显存和实际 token 数。全局索引不允许跨因果未来或打包文档边界。

若第一步稀疏已与预热方案等效，应接受该结果并停止制造新算法需求；若确有差距，再定位覆盖、监督或算子效率，并查该机制的最近工作。尚未确定模型规模与租卡配置，不使用旧 RunPod 状态作资源依据。
