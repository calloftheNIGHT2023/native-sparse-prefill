# D/W 两次初始化之后：验证实际计算成本

当前已完成的证据：随机初始化、全参数、第一步起采用固定局部 W，在两次匹配的初始化下，完整开发集 PPL 均低于密集 D。原始数据、固定终点、训练顺序和学习率已经核验。这个结果支持本小模型与 BabyLM 设置中的质量可行性，不建立统计非劣性，不代表学习式 QSA 路由已经得到改进，也不是新方法或完整 Qwen 的结论。

## 为什么下一步先量成本

目前 W 的 `local_attention_v0.py` 仍构造完整 QK 分数后加 mask。因此约四分之一的逻辑连接不能当成四分之一的计算成本。参考实现的顺序 FP32 训练时间也不能替代合理优化实现的比较。继续加训练轮次不能补上这一缺口。

## 实施顺序

1. **已有模型上的短时间分解。** 固定 D/W 最终模型与8个原训练窗口，先用不超过15分钟的诊断批次测量无插桩的整次前向/反向，并对不嵌套的 GDN、全局注意力、FFN 等模块单独记录前向耗时。函数式 LM head、loss、残差等留在未分配部分，不伪装成单独测出的 head 时间。本批无优化器更新；数据传输、梯度核对、日志和加载均在计时区域之外，因此不是完整训练步成本。调用固定36F/32B，窗口和代码SHA在执行前冻结。
2. **保持数学支持集不变。** W 查询位置 q 的可见区间应是 `[4 * max(0, floor((q+1)/4)-64), q]`，并在原文档边界重置。它不是直接截成恒定256个token的窗口。新的少算实现必须保留当前门控、GQA、RoPE、归一化、边界与参数，不把更改注意力规则混作内核优化。
3. **先验证输出与梯度，再计时。** 使用既有 FP64 oracle 和 GPU FP32 门槛；GPU完整支持及检查点重放沿用 atol=1e-6、rtol=1e-5，不能在失败后放宽。替换实现分别与自身 D/W 参考对齐，而非要求两个不同模型相等。精度切换需另立数值验证，不能混入当前 FP32 成本比较。
4. **给密集基线相同优化待遇。** 共同主干、精度、batch、序列长度、数据管线及日志设置相同；避免用优化后的稀疏与未优化的密集比。若 GDN 的参考实现开销遮蔽注意力收益，应先改善两边共同主干，再判断可实现的端到端收益。
5. **最后核对完整训练成本。** 交错重复测量，包含前向、反向、优化器、必要的mask/选择开销；分别记编译冷启动、稳定吞吐、峰值显存及包含数据/保存的墙时。只降低局部算子耗时不等于整个训练更省钱。共享GPU负载尚未隔离时，测量只能用于工程诊断，不能当论文中的受控时延数据。

第一阶段只定位当前实现的开销，不预先承诺加速幅度。CUDA事件记录同一stream上的区间耗时，包含调度等待和Python发射间隙，不是纯GPU核忙碌时间。模块前向占比不能冒充完整训练占比。只有在以后测得完整相应工作量中的注意力时间占比 a 后，才可讨论理想上界 `1/(1-a)`；不能把当前Python参考开销当成架构本质。

## 质量与论文证据仍缺什么

两次初始化都用了同一已观察开发集，不是两份独立测试集；正式 BabyLM 语言任务与更需要长距离依赖的独立设置尚未补齐。当前结果也不能区分局部归纳偏置、正则化或其他机制。若工程成本验证有价值，再冻结这些额外质量评测的数据与评分规则，并完成相关工作的贡献边界审查。固定局部窗口取得好分数本身不构成方法创新。
