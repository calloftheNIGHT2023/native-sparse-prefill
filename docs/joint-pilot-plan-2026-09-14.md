# 联合训练最小实验：先确认是否存在需要解决的差距

本计划在查看联合训练结果之前保存。前面的集合外均匀抽查与抽样normalizer均未通过门槛，停止这两条分支，不追加扫参或NLL评测来寻找正结果。

这一步是原问题所必需的验证工具，不是新算法。MiniMax Sparse Attention §3.2、附录B.2–B.4已经研究主干/索引器梯度、早期训练和预热；QSA报告§2.1.2给出了后期转换。不能把本实验中可能出现的冷启动差距写成首次发现。

## 固定设置

Pythia 70M的纯GPTNeoX架构，全部6层使用相同规则。两种起点：公开step1000权重、随机初始化。同一种起点各方法共用初始化和数据顺序，单个种子41。三组：完整注意力；第一步即选8个4-token块；先32步完整注意力、随后稀疏。尾块保留，严格因果。

预热组的主干也更新，是缩小的联合稠密预热对照，不冒充QSA冻结主干1000步的官方配方。索引器为经过尺度校验的缩小版。KL只更新索引器，LM loss更新主干；不宣称与Qwen混合架构相同。

排除之前112段正文及token前缀精确重复，使用WikiText原训练/开发/测试划分。新取256/16/32段，各256 tokens。每组256步、一个训练遍历、65536个训练token。相同AdamW超参；LM及索引器学习率1e-4，16步学习率预热，再余弦衰减。预热注意力阶段与学习率预热是不同的概念。

主指标为后128个位置的实际下一词NLL；开发集每64步测量，最终固定检查点测测试集，不挑最好checkpoint。稀疏模型另做一次完整注意力推理读出，作为掩码适应诊断，不改变主指标。

如果第一步稀疏比预热组在开发、测试均差至少0.02 nats，才把冷启动差距登记为可继续本地定位的信号。这不能自动批准付费扩训。三种子稳定性、长程能力与新颖性仍是扩大前的条件。

## 执行与限制

先检验完整注意力前向/反向与原模型一致、辅助梯度隔离、主干QKV有梯度、未来token不影响过去输出。每次运行保存每步UTC/单调时间、loss、梯度、token数、实际CPU时间、初始化/最终权重哈希、最终优化器状态及文件清单。

这里仍计算完整矩阵再施加掩码，CPU时间只用于资源估算，不是稀疏算子加速证据。256-token短段落不能检验长程任务；65536-token训练不能证明完整预训练质量。random组才是从随机初始化，step1000组是早期继续训练。

资源预检：本地70M稠密模型对随机token做了2个技术更新，首步约0.75秒、第二步约0.59秒。未保存这两步模型，也不计入科学实验；新增云支出0。

如这一最小实验没有可操作差距，不凭“训练能跑”要求用户租GPU。若需要更长训练来区分信号，先报告当前证据不足及具体资源瓶颈。
