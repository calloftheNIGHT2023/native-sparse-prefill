# 预训练主张与实验规模纠正

用户于2026-09-17指出数据规模、模型规模及训练token数与预训练主张不匹配。此意见优先于旧自动推进计划。现有结果保留为小规模LoRA继续语言建模诊断，不能支撑原生稀疏预训练、全参数训练或scaling-law结论。

## 已核实规模

Qwen2.5-0.5B已预训练基座；训练仅更新Q/K/V/O LoRA共1,081,344参数。WikiText-2训练包76×32768=2,490,368有效输入token，64步累计2,097,152、128步累计4,194,304 token/模型。后者包括数据重复。四条128步运行不能合并为一个模型的训练token。所有历史科学更新累计也不是一个模型连续接受的训练量。256本PG19书籍及其反事实题属于评测，不能加到训练量。

## Scaling law适用条件

Chinchilla研究从头全参数训练的模型/数据/算力分配，不是要求每段继续训练或LoRA适配重新达到固定token/参数比。其70B/1.4T示例约20token/参数；若仅作量级示意，0.5B×20约10B（100亿）token，远大于4.19M。但不能只用本次增量token除以基座参数来判定一个已预训练模型违反规律，也不能用LoRA的可训练参数替代总参数套同一式子。小模型可以研究预训练，关键是与问题相配的训练数据/时长、优化设定及可复现的尺度趋势；20不是普适强制阈值。

主来源：https://arxiv.org/html/2203.15556v1 。继续预训练也受初始模型、目标域及数据混合影响，不能只看D/N，参考https://arxiv.org/abs/2407.17467 。长上下文继续预训练的一个代表性研究用了约0.5B–5B token，并强调域平衡和长文本采样：https://arxiv.org/abs/2402.10171 。该规模不是所有任务最低门槛，也不照搬其128K设定。

## 当前结论必须降级

1. 稀疏LoRA短程适配在本机实现、当前0.5B/32K/两个种子上省时约7%–8%；不是全参数预训练成本结论。
2. 人工检索维持高分主要涉及保留基座既有能力；基座99.71%的天花板不能说明通过这几百万token学会了长文本能力。
3. 新书评测支持有限背景转移，不能替代扩大训练数据，也不能通过不断增加合成评测题把诊断升级成预训练论文。
4. 已知QK恢复与稀疏微调不是原创方法。固定步数省时不等于达到目标质量的最小训练成本。

## 后续优先级修改

当前book256-factorial是已经启动、最多2h/$1.48估算的封顶对照，仅收尾诊断并保存证据；不得在其后自动追加同类合成题或直接扩大旧LoRA方案。持续授权仍有效，不是用户叫停。

下一项应先完成规模与预算设计：冻结来源明确、去重、训练验证分离、保留文档边界的长文本语料；WikiText-2退出主训练语料候选。若主张是继续预训练，优先评估全参数训练可行性，0.5B作可控实验，较大模型仅作预算内复核候选。初步候选token档位100M/300M/1B，用来判断质量与成本趋势，尚未授权为已冻结运行计划；这些档位不保证论文充分性，也不是声称满足某个通用scaling law。单条长轨迹的中间断点不能自动当作学习率匹配的compute-optimal独立训练。

先在空闲GPU上做有限全参数显存、吞吐和稳定性测量，再根据实际token/s、失败余量和现存预算选择运行矩阵。不得用旧LoRA吞吐直接承诺全参数成本。独立比较等token、等GPU时间及达到固定质量所需成本；关注验证NLL曲线和自然长文本任务，不只检索保留。若研究从头原生稀疏训练，则另行设计较小随机初始化模型和充足语料，不能继续用当前LoRA实验冒充。

训练规模修订未完成前不得启动新训练或新增合成检索批次。预算上限沿用既有记录，用户批评规模不足不是无限预算授权。旧结果、失败、源码哈希与冻结协议不改动。
