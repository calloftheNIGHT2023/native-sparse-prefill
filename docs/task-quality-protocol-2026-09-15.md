# 任务效果与prefill评测：冻结协议

目的：判断已观察到的PPL约+6.3%、训练耗时约-9.2%是否转化为可接受的任务正确率取舍。只评测已有四个断点，不新增训练。dense LR3e-4和K16 LR1e-3，各两个初始化种子，同为256步。

任务采用RACE-M原始四选一阅读理解，以及自建键值检索四选一诊断。RACE来自ehovy/race，版本2fec9fd81f1dc971569a9b729c43f2f0e6436637；保留原问题、选项和正确答案，重新排列选项，使A/B/C/D平衡。使用不同原始文章区分validation能力检查与test正式题。不能称为官方RACE或LongBench分数。检索诊断借鉴可控检索的评测思路，未运行官方RULER生成器，不能称为RULER成绩。

先用dense种子0检查每类32题，比较短原文和无原文。阅读理解至少16/32正确且上下文带来至少4题提升；检索至少24/32正确且至少8题提升，才继续该类正式评测。这是排除任务能力过低的操作门槛，不是统计证据。失败类别停止，不能拿双方都不会做当作效果接近。

每类正式96题，固定四种输入：短原文、移除原文、扩充至8192和16384 token。长输入中完整关键段落保留，分配至无关文本的10%/50%/90%位置，每位置32题且答案位置均衡。无关段落来自RACE训练集，排除validation/test相同文章。输入明确标注TARGET段落，因此这是可控长距离阅读/检索，不是自然多文档问答。协议和全部样本在能力检查前写入SHA清单。

当前模型是基础模型，采用固定两示例提示，在输入末尾比较单token的A/B/C/D得分，选择最大者。主指标为选项正确率，不要求模型自由生成答案，不测decode。记录全部四项logit、标签概率质量、原始预测和逐题时间。每个断点仍需通过原校准NLL复算≤1e-6，以及原配置、权重和源码SHA检查。

prefill计时：batch1，完整主干前向+末位置输出头，CUDA同步的墙钟计时；不含分词、输入搬运、模型加载、结果传输。每个模型先做3次短输入热身。同一道题、同一输入token逐项配对，模型顺序dense0/sparse0/sparse1/dense1。当前一次连续运行只提供条件性耗时，不能当成多轮硬件性能统计。

按任务与长度报告两个种子的正确率差（百分点）、退步题与进步题、答案改变率，以及配对prefill时间比。对同一题在两种子上的差异先平均，再按题bootstrap；长度之间不混为独立样本。探索性“差不多”参考5个百分点：只有描述性95%区间下界高于-5pp且dense超过随机水平才可称该样本支持这个容忍范围。未显著不同不等于等价；96题不足以保证严格等价。新题评测结果不得用于改答案或筛选有利样本。

最多1200秒控制器、单进程360秒，无自动重复失败任务。只有通过能力检查的任务进入四个固定断点比较。逐步日志、原始预测、完整UTC时间轴、配置、输入及SHA清单全部保存。若能力检查失败，下一步先改评测形式或换合适规模模型，不宣称稀疏质量等价。
