# 低预算研究路线：先确认机制，再做最少的关键重复

2026-09-13。用户指出原预算无法承担，随后确认 GPU 总预算为 500 美元。本文件替代旧版多阶段预算作为当前执行入口。旧预算保留为历史情景，不再默认推进其中的重复验证与规模扩展。

## 缩小问题

当前只问：在小模型与固定计算预算下，给 QSA 索引器增加集合外比较，能否更快发现此前漏选的重要信息，并改善实际预测？

暂不承担“Qwen 级别模型从头全程稀疏训练更优”的证明任务。原生稀疏训练仍是背景；若只有小规模机制证据，论文主张必须相应收窄。此路线的贡献重合尚未排除，不能把低预算方案视为已确定的论文贡献。

## 阶段 A：本地准备与诊断

- 使用本机 CPU 做掩码、采样、索引目标和梯度路径的正确性参考。读取到的本机 GPU 是 RTX 5070，约 12 GB 显存；是否能运行目标模型需实测。检查时占用约 5.7 GB，不能假定全部显存可用。
- 构造可控的小规模上下文任务，检查遗漏信息何时可以被重新选入。对比仅选中块监督、集合外抽查和全量监督参照。
- 在共享输入与固定候选池上比较索引器学习，只能回答机制问题；冻结主干的回放不能证明联合训练有效，也不能冒充不同训练随机种子的重复。
- 若正确性与可控任务均无可解释信号，停止该具体改动；先处理实现或机制问题，避免租卡盲试。

这一步不新增云 GPU 租金；本机电费与使用时间不是零成本。此文没有启动本地训练或关闭其他程序。

## 阶段 B：少数组别的小模型端到端筛查

以约 30M–80M 参数、2K–4K 上下文作为待测起点，保留索引器监督问题；纯注意力简化若先用于调试，需要标注与原混合架构的差异。显存、吞吐和学习行为通过短测确定后才冻结正式配置。

首轮最多三组：

1. 原版仅选中块监督。
2. 增加集合外抽查。
3. 短稠密预热后原版监督，作为关键竞争解释；预热成本计入总成本。

每组先用相同的初始化种子与数据顺序做一组配对筛查。固定数据划分、测试集和主读出。记录损失/任务分数随实际 GPU 时间的曲线，从同一训练轨迹同时读取同 tokens 与同成本的预先指定位置，减少为两个比较口径重复训练的费用。不同方法必须各自计时，抽查辅助分支、预热和评测都入账。

缩短上下文时不能沿用原本 512 个微块的固定 top-k，否则小序列可能接近全注意力。冻结能保留真实未选集合的比例，并记录每个 query 的因果可见块数、实际 k 和抽查数。

单种子用于排除明显无效或错误实现，不用于稳定性结论。小模型/短上下文上的阴性也不能说明原方法在大模型上必然无效；在本预算内可以因此停止投入。

## 阶段 C：只重复决定结论的比较

- 仅当开发集预先规定的主指标有信号，才重复候选方法与关键基线。关于“减少预热”的主张必须包含短预热基线，关于“抽查的作用”必须保留无抽查基线；不得仅因某个基线更强就删掉它。
- 优先两到三组、合计三个独立训练种子；方法间配对初始化与数据顺序，种子间独立。复用数据缓存和相同初始权重文件可降低准备成本，但方法间的训练必须独立执行。
- 可将共同轨迹中预先指定的时间点用于比较，但一个训练过程的多个检查点不能当成独立重复；测试样本 bootstrap 也不能代替训练随机性的重复。
- 如果三种子或必要基线超出总额，交付探索性结果并降低主张，不能用省略重复来声称结果稳定。新的规模扩展没有默认预算。

## 费用约束

500 美元是本研究线的总上限，包含云 GPU 的初始化、编译、训练、评测、失败重跑和计划内存储。预留 100 美元余量，正常工作最多分配 400 美元；不以花完预算为目标。
