# 官方 FlashMoBA 基线实测

官方算子已接入现有 RTX 6000 Ada 并完成验证。这是基线复现与运行框架建设，不是新方法的质量提升。

## 正确性

官方完整 API 的 12 条检查通过。包括 FP16/BF16、MHA/MQA/GQA、非整块与变长序列、同支撑 FP32 前向/梯度核对，以及修改未来 K/V 后前缀不变。

首版 gate 在第3项停止，因为把官方均值当成 FP32 求和。源码和额外诊断显示，官方 Triton sum 保留输入浮点 dtype；外层 acc=FP32 并不使内部归约成为 FP32。v1 使用同一份实际均值核对路由，并另外记录它相对理想 FP32 均值的选块差异；评分 regret 门槛和前向/梯度误差门槛未放宽。它验证的是当前实现，未宣称低精度池化与理想 FP32 完全一致。

6份保存的诊断输入另外检查了 FP32 池化；误差与选块变化见 results/flashmoba-pool-precision-v0。尚未在语言模型上证明该数值修正提高质量，普通提高精度也不计新方法。

## 可选 CUDA Graph 检查未通过

固定 metadata 包装器只缓存长度与分配大小，摘要和路由每次重算。前两条 FP16 小形状检查通过，包括改变输入后 graph 输出仍正确；第3条 8192×8×128 录制失败，未继续执行完整 graph 性能表。这里不把局部成功写成整个包装器通过。

随后用各自独立进程隔离组件，结果：mean=passed, route=passed, sort=failed, attention=passed。详情与完整异常保留在 results/flashmoba-graph-component-v0。该环境/形状的结果不能推出所有版本或形状都不支持 CUDA Graph；本轮主表只使用普通完整调用。

## 能说明什么

这批结果只回答实现是否正确、现有硬件上的注意力算子成本。随机 QKV 的速度不能证明长文本答案质量；旧 token-top8 模型的准确率也不能移植给整块 MoBA。源码、训练环境、梯度路径已对齐，后续改动可以在真实优化基线上检验。

本轮新增模型训练为 0，优化器更新为 0，原创贡献仍为 0。边界移动、边界补连接、RoPE 均值摘要修复存在直接相关工作，暂不按这些宽泛提法开长训。详见追加查重报告。

## 环境与记录

Python3.11 / torch2.8.0+cu128 / Triton 随该版本安装；编译 toolkit12.9.1，官方 commit39d9ac043b271d046a2181a9991e99a26b67bca1。旧torch2.4.1环境保留，主机驱动未修改。

共36个计时条件（24个 prefill、12个前向＋反向），12条完整 API 检查、6条池化精度复查。可选 metadata gate 未通过，4个组件诊断分开记录，不算性能结果。首轮编译受控中断后续编，再修复头文件搜索路径；这些都不是科学训练失败。

逐条件样本、源码快照、UTC 和错误日志均在 results/flashmoba-* 与 logs/flashmoba-*.log。审计 results/flashmoba-stage-audit-v0/audit.json。原始/失败批次均保留，失败不计入通过数。路由定位用的小诊断仅保存结束 UTC，未记录精确开始时刻，不补造时间。GPU任务结束不代表 Pod 停止，实际账单未知。
