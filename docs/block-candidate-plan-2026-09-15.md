# 粗选候选再做 top-8：本轮边界和实验设计

上一阶段每个 query 仍对所有 key 打分，prefill 未得到稳定加速。本轮检查能否用已知块摘要先排除多数 key，然后在候选里保留与原模型一致的“两条局部边＋六条远端边”。这是确定后续研究成本的基线，不宣称新算法。训练更新为 0。

## 相近工作核查

- [MoBA](https://arxiv.org/abs/2502.13189)：块内 key 平均值打分，选择远端块并保留当前因果块。我们借用其粗选思路，但最终只选 8 个 token，并非复现 MoBA 完整算法或训练结果。
- [Optimizing Mixture of Block Attention](https://arxiv.org/html/2511.11571v1)，§2–4、§5 表格、附录索引：已有路由信噪比分析、小块、key 卷积和 FlashMoBA kernel。不能把“平均值稀释少数关键 token”“用更小块”和“融合选块”单独作为新贡献。本轮没有复现论文实验。
- [Quest](https://arxiv.org/html/2406.10774v1)，§3.1、3.4：已有按 key 各维最小／最大值估计块分数的方法，主要优化 decode 的 KV 读取。本轮将此**已知评分规则**用于所有 prefill queries 的候选预筛，不把 Quest 的 decode 加速数字当 prefill 证据。
- [Uncertainty-gated selection for block-sparse attention](https://arxiv.org/html/2607.07724v1)，摘要及方法定位：已有用截止附近分数间隔决定额外选块的预印本。因此“遇到模糊边界就多留几个块”也不是已确认的空白。未独立复现其结论。

原件、URL、下载时间和 SHA 在 `literature/block-candidate-2026-09-15/`。本轮为针对性重合筛查，不是穷尽查重，也不是所有论文全文精读。确认原创贡献仍为 0。

## 实验顺序

1. 已暴露的 MQAR：块大小 8/16/32，选 1/2/4 个已完成块，分别用均值与 min/max，共 18 档；当前块只使用因果位置。两个冻结模型、原来的三个 split 全部报告。与 exact top-8 对照逐答案比较。
2. 每层读取冻结的 Q/K/V，检查 top-6 召回、保留注意力质量、输出误差。候选证书统计使用事后已知的真实 cutoff，**不是实际可以免费得到的路由器或加速**。
3. 在第一轮后选定 b32/r4 做新题复查：固定四个块边界偏移 0/8/16/24；再做较小候选、单层替换和均值负对照。`data/block-candidate-confirmation-v0/preregistration.json` 在新题预测前固定条件与严格逐答案一致标准。
4. 新题 seed 2026091511，1024 条；噪声 seed 2026091512。与旧训练 100000 条、开发 3000 条及已保存的多个测试集按输入哈希排重；干净、换值、噪声是成组变体，不算三批独立样本。
5. 云端 RTX 6000 Ada 上测 BF16 的所有 query：N=1024/4096/8192，1/8 头。均值/minmax 原型、exact top-8、强制 FlashAttention 均测 eager 和 CUDA Graph；每次都重建摘要与候选，预热/捕获单列。随机张量计时不能证明长上下文质量。

## 判断

保持答案但还慢：候选方案有质量可行性，工程尚未完成。
更快但只在随机数据上：仅为计算证据，不能与 N256 的质量拼成一个长文本结论。
新题或边界变化失败：保留失败与差异，不把旧题上的一致性改称普遍保证。
这些基线通过也不自动形成论文；仍需明确超出相近工作的具体贡献及真实文本上的训练、质量、实际速度证据。
