# 完整研究记录、结果与后续计划

返回 [README：如何改进稀疏化](../README.md)。

本项目研究：**能否从随机初始化开始，全参数、第一步就使用稀疏注意力，以更低的实际训练成本达到接近密集注意力的语言质量？** 当前实验载体是 BabyLM 数据上的小型 GDN＋全局注意力混合模型，不是完整 Qwen 架构复现。

**最近完成：** 一轮 D/E 对照、索引器分数尺度修正 F、固定局部基线 W，以及第二个初始化种子的 D/W 确认和小型耗时诊断。W 在两个种子的完整开发集上均有更低 NLL，但实际成本改善尚未证明。当前没有足以声称“新方法成立”或“论文主张已获支持”的证据。

**下一步候选：** 先验证 D/W 共用的 GDN 单文档快速路径，再判断是否值得实现真正跳过无用计算的局部注意力。该优化目前只有方案，未实现、未运行；不是继续堆训练轮数。

本页按实验族覆盖已完成、失败、中止及拟做工作，日期使用 UTC；逐次运行、迁移、计数与失败细节见 [TIMELINE.md](../TIMELINE.md)，交接状态见 [STATE.md](../STATE.md)。文档是研究记录，不是启动作业的授权；自动监控当前暂停。

## 1. 先看结论与边界

| 问题 | 当前证据 | 还不能声称什么 |
|---|---|---|
| 从第一步使用稀疏连接能否训练？ | 小型混合模型的 E/F/W 均完成随机初始化、全参数、一轮训练。 | 不能外推完整 Qwen、大规模收敛训练或计算最优 scaling law。 |
| 原始学习式路由 E 是否有问题？ | 一轮完整 dev 比 D 差；训练中多数路由 query 出现全零分数。 | 不能只凭相关性断言全部语言差距由这一机制导致。 |
| 改分数尺度 F 是否有帮助？ | 完整 dev 优于 E，但仍差于 D 和固定局部 W。 | 不能称新路由方法、冷启动已解决或有独立创新。 |
| 是否需要学习式索引器？ | 无索引器 W 在第一种子优于 D/E/F；第二种子再次优于 D。 | 尚无证据说明当前设置需要学习远程选块。 |
| 是否已省钱、加速？ | 有小型前向组成诊断；历史 LoRA 有特定条件下的耗时记录。 | 当前 BabyLM 仍算完整分数再 mask，尚无端到端稀疏省时证据；旧 LoRA 时间不能代替。 |
| 能否作为论文结论？ | 有可复算的质量观察、负结果和实现问题。 | 两个初始化、同一开发集与数据顺序，不构成一般性结论、统计等价或论文充分证据。 |

## 4. 当前一轮实验究竟控制了什么

### 数据、窗口与模型

- **数据：** BabyLM 2026 Strict-small 六个训练源：BNC spoken、CHILDES、Gutenberg、OpenSubtitles、Simple Wiki、Switchboard；原始合计 10,000,000 个空白分词的词。train-only ByteLevel BPE，词表 16,384，不复用预训练 tokenizer。
- **边界：** 物理行保留为可追溯记录，不直接冒充真实文档。以源文件和明确标记定义强制段边界；上游隐藏的抽样／拼接边界未全部认证。非重叠切成至多 2,048 token，保留尾窗，不跨源／明确标记拼接，每窗重置位置、注意力及 GDN 递推／卷积状态，默认不加 BOS/EOS。
- **一次遍历：** 22,598 个训练窗口，16,325,414 输入 token，16,302,816 监督 token，保守记账 10,001,709 次词暴露。词暴露略高于原始词数来自跨窗口记账，不是增加语料。
- **模型：** 12 层中 9 层 GDN＋3 层全局注意力；hidden 768、FFN 2,048、全局 Q heads 6／KV heads 2／head dim 128。D/W 为 95,391,000 参数；E/F 额外 1,475,328 索引器参数，总计 96,866,328。
- **更新：** 全参数随机初始化；配对条件的共同参数完全一致，索引器使用独立 RNG。16 窗／更新，按监督 token 加权梯度累积，一轮 1,413 更新，最后一组 6 窗。
- **评测：** 固定完整 dev 18,792 窗，17,437,534 输入 token、17,418,742 监督 token；无监督目标的窗口保留记录。48 窗面板只用于过程观察，不代替完整 dev。

数据细节见 [边界审计](../docs/babylm-document-boundary-audit-2026-09-17.md)、[tokenizer 账目](../docs/babylm-tokenizer-accounting-2026-09-17.md)、[窗口规则](../docs/babylm-window-policy-2026-09-17.md)。这是一轮、数据受限的早期训练实验：输入 token／主干参数约 **0.17**，不能宣称计算最优配比或收敛预训练。短文档切成 2K 窗也不会自动产生真实长距离依赖。

### 条件定义与学习率

| 代号 | 三个全局注意力层如何工作 | 索引器／辅助损失 | 当前执行情况 |
|---|---|---|---|
| D | 密集因果注意力 | 无 | 一轮两个初始化种子；另有历史十遍实验 |
| E | 从第 0 步学习式分块稀疏，原索引分数尺度 1 | 有 | 一轮一个种子；另有历史十遍实验 |
| F | E 的单因素修改：索引分数尺度 1/√128 | 有，LR 与 E 相同 | 500 步筛查＋同轨迹续至一轮，一个种子 |
| W | 最近 64 个完整的 4-token 块＋原因果不完整尾部，无 sink | 无 | 一轮两个初始化种子 |
| L | 先密集／索引器预热，再切稀疏 | 尚待固定具体公平方案 | 当前 BabyLM **未执行**；早期其他模型预热实验不能替代 |

W 的零基 query 位置 q 可见区间为 `[4*max(0, floor((q+1)/4)-64), q]`。因此它不是简单的恒定 256-token 滑动窗；尾部可使可见长度随位置变化。当前参考实现按完整分数张量施加这些连接限制，逻辑稀疏不等于计算稀疏。

一轮共同训练配置：AdamW，主干 LR `3e-4`，betas `(0.9, 0.95)`，eps `1e-8`，weight decay `0.1`；前 100 万词 warmup，按完整一轮余量 cosine 至 `3e-5`。E/F 索引器 LR `1e-3 → 1e-4`，使用同一调度倍数。主干和索引器分别 clip norm 1；FP32、关闭 TF32、固定确定性设置。B2 500 步沿用原 1,413 步调度前缀，不把 cosine 压缩到 500 步。**学习率 warmup 不等于先密集注意力再稀疏。**

## 6. 速度、成本、计数与备份：已完成到哪里

**当前 BabyLM 没有证明实际加速或更低费用。** E/F/W 的参考路径仍分配完整注意力分数；学习式路由还多索引器开销。历史 FlashMoBA/LoRA 的速度结果不能迁移为本实验的原生预训练成本证据。

最新完成的是固定权重、固定 8 窗的工程诊断：

- 36 次前向（含 4 次无梯度预热）、32 次反向、0 次优化器更新，总墙钟约 43.86 秒；权重保持不变。
- 16 组无钩子／带钩子配对，每组核对 146 个具名参数，共 2,336 条梯度记录，使用原 `atol=1e-6, rtol=1e-5`，不放宽标准。
- GDN 占**带钩子前向**的合并耗时为 D 82.48%、W 80.12%；全局注意力为 D 11.18%、W 13.33%。不能把该比例当作训练 F+B 占比或据此计算训练加速上限。
- GPU 是共享环境，两次利用率快照均为 100%；样本按长度分层而非全语料权重；首次反向冷启动未删除；钩子与无钩子的时间差混有噪声。未计完整优化器、梯度累积、数据流水线、保存与评测成本。

因此该结果只支持“先检查共同 GDN 实现开销”，不支持 W 已经更快。具体见 [诊断报告](../evidence/reports/babylm-dw-cost-profile-audit-20260921/REPORT.md)。

第二种子成功的 D/W v1 合计：**45,196 次训练 F/B、2,826 次更新、672 次面板前向、37,584 次完整 dev 前向**；总前向 83,452、总反向 45,196。最初 v0 中断、F 的恢复重算、工程诊断及旧 LoRA 均另记，不从成本账中抹掉，也不混作有效训练暴露。

最终 D/W model-only 权重已在本机完整备份并逐 SHA 校验；优化器和所有中间状态不全部在本机，**model-only 不能当完整恢复点**。GitHub 不包含这些模型。各阶段 GPU 租价／上限是阶段记录，不是全项目账单；当前新主机实价未确认，累计真实美元支出不可凭空补全，未知值也不等于零。

## 7. 后续计划：按顺序过门槛，不默认全部开跑

### 下一项：D/W 共用 GDN 单文档快速路径（仅计划）

动机是当前分段封装每层都执行 GPU `segment_ids.tolist()`，随后 `zeros_like → index_copy → stack`。单个已知窗口可能不需要重复分段。具体方案见 [下一步设计](../docs/babylm-common-gdn-next-step-2026-09-21.md)。

1. 保留冻结科学源码，新增独立适配器；D/W 同样优化。只有已验证的 batch=1、连续单文档、无 padding、每窗重置输入，才可直接调用原 `self.core(x, cache_params=None)`。
2. 由核验清单与 token SHA 的读取器提供、并绑定实际输入的可信 CPU 元数据授权；不能仅凭形状／默认布尔标记忽略任意 segment IDs。多文档、padding、其他 batch、信息缺失走原通用路径。
3. 保持数学算子、权重、精度、归一化、卷积与状态重置不变；先测 63/64/65-token 边界和隔离／回退，再核对真实窗口 logits、LM loss、全部具名梯度，沿用 `atol=1e-6, rtol=1e-5`，0 参数更新。
4. 固定有界 8 窗，交替原版／适配器测 F/B 与同步墙钟，单列检查开销；没收益就停止扩大。这仍是模型 F/B 诊断，不冒充端到端训练。
5. 只有确证实际调用的 GDN chunk 实现仍有主要开销，才考虑固定形状编译等下一项独立候选；先冻结新协议、验证等价和编译成本，不凭警告猜内核路径。

### 随后：真正稀疏的 W 实现与完整成本对照（未执行）

见 [成本验证计划](../docs/babylm-dw-cost-validation-next-2026-09-21.md)。保留 W 精确可见范围，真正避免完整 QK 计算；D 使用合理优化的密集实现，两者相同精度、batch 和共同主干优化。先做输出／反向等价，再在同一受控 GPU 上交替重复，分开冷启动／编译与稳态。

计入训练前向、反向、优化器、数据处理、选择器／辅助项、评测和保存；报告显存与波动。最终分别回答等数据暴露的质量、等实际预算的质量，以及达到预设质量的总成本。如果真实成本没有改善，继续承认未满足原题，不能靠逻辑稀疏比例或只报算子时间补足主张。

### 满足条件后才做：质量、机制与泛化确认

| 候选 | 要解决的缺口 | 启动条件／判断方式 |
|---|---|---|
| 真实 BabyLM 语言任务 | 目前只有 dev NLL，任务代码只测过手工样例。 | 先固定官方版本、真实数据、评分与汇总规则；明确完成哪些任务，不能把部分接口称完整套件。 |
