# 首对 D/E 先导的阶段证据与诊断约定

本文件落实审稿自评，不新增方法或训练组。科学训练仍未开始；配置仍是 `launch_allowed=false` 的草案。优先测得随机初始化、全参数、step0 稀疏的实际学习曲线，再决定是否值得解释及扩大。它不恢复旧 LoRA 线路。

## 阶段权重与真实账目

候选科学配置在累计词暴露首次越过 1M、2M、…、10M、20M、…、100M 时保留 model-only 快照。阈值是名义检查点，快照名和内容记录实际累计词、输入 token、loss token 与更新数。整批不能拆开，允许越过阈值后保存，但必须报告真实超出量；一批越过多个阈值只存一份权重。

自然结束或一次受控暂停也保存当前权重与停止原因。阶段权重不含 optimizer/RNG，不能直接声称能原样续训；最近一次完整 optimizer/RNG checkpoint 仍负责严格恢复。若从阶段权重分叉诊断，必须明确是否重置 optimizer、单独冻结干预协议，不能混成原训练轨迹。

固定顺序预计停在 99,998,882 词；100M 阈值未达到就不标记达到100M。最终快照按真实计数保存。已有阶段快照与最终点相同，则仅增加最终收据，不复制整份权重。恢复时核验快照/收据哈希及已跨阈值，既不覆盖旧证据，也不重复保存已完成的阶段。失败快照继续保留。

D/E 共用的95,391,000参数与E额外1,475,328参数，以FP32存储：一组阶段权重约0.38–0.39GB。若每组有19个不同保存点，两组仅阶段权重约14.6GB（十进制），另加最新 optimizer checkpoint、写入临时空间和失败记录。首跑磁盘至少预留25GB可用空间并核查实际文件系统是否支持快照的原子 hard-link 发布；暂停次数多时还须增加。保存与备份时间、存储费用都计入真实成本，不能当作免费。

## 每个训练更新的廉价诊断

保留主干和 indexer 的裁剪前梯度 L2 范数、共同全局裁剪系数、主干/indexer 学习率、实际词位置、LM CE、aux 权重和加权 aux。它们读取本来已产生的梯度，不增加模型前向/反向，不改原有全局裁剪或 optimizer。

这些是组合目标产生的梯度范数，不是分别对 LM 与 aux 做梯度归因。indexer 若拖低共同裁剪系数，记录可提示优化耦合，但因果判断仍需后续单因素干预。禁止仅根据范数相关性宣布冷启动机制成立。

## 同一次开发评测中的位置诊断

固定按 query 已可见的窗口内输入数分桶：1–256、257–512、513–1024、1025–2048。query 预测紧随其后的 token，窗口首 token 不作目标。它们是重置后的窗口位置，不是整本文档位置。

使用同一次 forward 的 logits 重算逐 token CE，按源、位置桶、整窗长度桶和窗口保留总损失与目标数；核对这些归约与模型 LM loss 一致，不纳入 aux。每桶以总损失/总目标数计算，不平均各窗平均分。分桶多一次 CE 归约，有真实运行开销，但没有新增模型 forward/backward。空桶标为无数据，不能填0成绩。

固定 block=4、top64 完整块时，query 历史长度达到260才首次删减完整块。训练有效目标中77.3039%在确实删边的query处；完整dev为80.2440%，48窗过程面板为86.0489%。这是布局覆盖率，不是速度或能力结果。

## 看见曲线后能做什么、不能做什么

D/E仍只是一对配方比较：平均分接近或尾部差距，都不能单独归因于冷启动。这里不把相关token当作独立重复，窗口也不冒称已核实的独立文档。48窗面板是过程诊断，不用于最终显著性/等价宣告。

路由支持变化和历史截断反事实留给已保存阶段权重上的固定probe：沿用同一48窗，比较预定阶段，不按差距挑窗；每个额外forward单列预算与费用。当前尚未实现/执行这些probe，不能在结果中声称已经记录支持变化。GDN仍保留同窗历史，所以限制global层连接的效果只代表这些额外连接的边际作用。

第一对曲线后先选最有信息的一项对照：若E近似D，考虑匹配可见边数的局部W；若E存在可重复观察到的差距，先根据数值/梯度记录选择具体单因素诊断。没有自动12组训练队列，没有把“跑完规定数量”当作论文贡献。

当前尚缺可用GPU连接、实际报价和已支出/剩余预算核对；CUDA数值、真实吞吐和完整两组可负担性也未实测。正确性reference允许有界质量先导，但其完整分数计算不能证明稀疏加速；合理优化dense的可替换attention占比和真正稀疏端到端实现是后续成本主张的独立证据要求，不用逻辑边比例代替。

## 本机实现核验与语言评分接口边界

阶段快照/梯度记录5项定向独立检查首轮通过，主干及indexer梯度与独立展平计算一致，D/E参数更新与标准AdamW参考计算最大差均为0；包括真实tiny模型的同forward位置诊断。共7次tiny完整模型forward、6次backward和6次工程更新（4次引擎、2次独立参考）。这不是BabyLM科学训练。

位置诊断4项检查及原dev评测7项检查的最新结果通过。新测试首轮出现3个fixture错误：Windows NumPy remainder产生的uintc别名无法交给torch，发生在调用假模型之前；修正为与读盘相同的明确uint32构造后4项全部通过。原始失败报告仍保留。这里没有新增完整模型计算。

`src/babylm_hybrid/official_causal_scoring.py` 提供最小normalized-record causal打分接口，已与固定BabyLM官方commit `6f825c291e2c4c78ad33b1935fd64d45f52642dc` 的处理/shift/offset/打分代码对照。当前只覆盖句子/续写概率，不声称已接通数据reader、准确率/tie汇总、阅读/AoA/微调任务或完整官方评测。没有下载或读取正式评测题与答案。

评分接口初轮9项通过，其中3次真实tiny CPU forward检验padding/adapter与独立调用；只读审查再发现异常计数丢失与极小温度可能产生非有限分数的问题。修正后9项fake-only检查通过，未重复真实模型调用。每次源码哈希与计数保存在 `results/babylm-official-causal-scoring-v0/history.jsonl`。默认固定temperature1；不根据测试答案选温度，不额外加入训练从未使用的BOS/EOS。空评分目标保留官方0分行为但禁止据此排序。

本轮合计新增完整tiny工程10F/6B/6更新，项目累计82F/61B/35工程更新；科学预训练、实际BabyLM训练token和GPU调用仍为0。阶段代码改变只证明准备工作完成了一部分，不是质量/成本结果，也未获得论文贡献证据。
