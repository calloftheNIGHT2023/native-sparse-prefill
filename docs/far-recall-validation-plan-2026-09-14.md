# 先确认实验确实需要远处信息

前两次自然文本控制得到小幅全局上下文收益，但测试集未达到固定门槛。现在增加一个答案明确、信息来源可逐位置核对的诊断：在前面放多组“编号→数值”，在末尾问其中一个编号对应的数值。每组样本只改变远处的正确数值，问题、附近内容及其他记录保持相同。

这项工作用于验证实验工具和任务，**不作为新选题或原创算法贡献**。也不会把人为让固定局部注意力失败包装成学到的稀疏路由失败。

## 与前作的关系

- [MAD，§3.1.1—3.1.3、附录B.1](https://arxiv.org/html/2403.17844v2)：已使用关联回忆、噪声回忆等任务，键和值使用不同词表，映射在不同样本之间变化；用于便宜的小规模能力检查。这里采用同类任务，新增的反事实成组和可达性审计仅是本项目实验控制，不声称首次提出。
- [RULER，引言和检索任务介绍](https://arxiv.org/html/2404.06654v3)：已有可配置长度及复杂度的合成检索任务。单一检索指标不能代表全面长上下文能力。
- [Zoology，摘要](https://arxiv.org/abs/2312.04927)：已有对高效语言模型关联回忆问题的研究。本轮只核对摘要，没有把它称作全文精读。

原页面与哈希已保存于 `literature/far-recall-check-2026-09-14/`。这不是穷尽查重；不据此断言反事实或可达性控制不存在相同前作。

## 2K数据已固定

使用256个离散符号，键、答案、填充符号分属不同集合；不是自然语言tokenizer，也不是指令数据。

- 2048个输入位置，最后一个位置预测答案；标签不附在输入末尾。
- 16组记录、64种键、16种答案。记录位于索引64—447，末尾问题查询其中一条。
- 同一家族生成16个反事实版本，正确值逐一覆盖16种答案，其他输入完全相同。家族种子按train/validation/test分开，完整家族哈希也无交叉。
- 训练256家族/4096条，开发32家族/512条，测试64家族/1024条。统计单元是家族，不能把同一家族的16个版本当作独立样本。
- 完整内容的符号查表器在全部5632条上答对；它是读取输入的程序上界，**不是神经网络实验成绩**。

## 多层路径必须一起检查

沿用当前模型的6层、每块4tokens、每行共64个完整块，其中一个是开头块，其余是最近完整块，并保留未满块尾部。实际掩码计算表明：最后一个输出经过六层能依赖的位置为0—3及536—2047。证据所在的64—447区间不在其中。

令每层静态注意力支持矩阵为 $A_\ell$，查询位置为 $q$。从最后一层反向计算

$$R_0=\{q\},\qquad R_{t+1}=R_t\cup\bigcup_{i\in R_t}\{j:A_{L-t}(i,j)=1\}.$$

在位置独立的MLP、归一化和残差下，最后输出只依赖 $R_L$ 内输入。这是对计算图的基本检查，不是新理论贡献。反事实家族在 $R_L$ 内输入完全相同，标签均匀覆盖16类，故固定、确定性的局部模型只能输出相同预测；限制到16个答案类别的准确率恰为1/16=6.25%，允许输出其他token时上限仍为6.25%。随机解码只给期望上限，实际测试禁用dropout和随机采样。

**适用范围有限：**这个界仅针对静态开头+附近对照。内容相关的索引器可能通过选块传递额外信息；Gated DeltaNet等递归路径也能传递远处信息，不能把该界套到完整Qwen混合架构或所有稀疏模型上。

## 四项检查

1. **删掉证据：**所有版本变成完全相同输入，完整模型也应失去辨别能力。
2. **证据移近：**将同一条记录移到末尾附近，确认局部模型现在存在读取证据的路径。移动后未训练过的模型不一定答对，因此还需要报告这是否属于位置分布外测试。
3. **正确位置已知的选块：**只在末尾查询行，用正确块替换一个已选块，完整块数量不增加。这是借助标签位置的上界检查，不是可部署新方法。
4. **完整模型能学会：**先用CPU上的小GPTNeoX做128长度可学性检查，最终开发及测试准确率均至少80%才视为通过。只选固定最后一步，记录失败或时间上限；不按测试集挑检查点。128长度通过不等于70M/2K已通过。

## 本轮成本与后续条件

本轮只做本地数据、图结构检查、CPU训练和现有70M模型的CPU前向检查，不启动云端作业。旧Pod是否停止仍需用户控制台确认，不能把“本轮没有GPU作业”写成“旧机器已停止计费”。

下一轮GPU首先测70M/2K稠密模型能否在全新家族上完成任务，再对照同一权重下的固定局部、删证据及正确位置已知的选块。只有这一条件成立，才比较从第一步稀疏和预热后稀疏；否则不能拿一个连完整模型也不会的任务评价索引器。即使任务区分明确，提出新方法前仍须单独核对贡献重合。

任何论文层面的结论都还需要更真实的任务、独立训练种子以及Qwen混合路径验证。当前数据和小模型结果只能支撑诊断。

## 执行后修订与暂停扩大

当前2K数据为`data/far-recall-v1/`，使用完整SHA种子驱动的PCG64，末尾格式为“问题标记、分隔符、查询键”，直接在键的位置预测答案；v0保留。流式v1发现旧Torch CPU种子低32位相同导致题族重复，3142步后停止；PCG64回归检查通过。不能把不同生成器/查询格式/数据种子版本的结果当成单因素对照。

固定题库和修订后的新题流均未通过128长度可学性门槛，最终测试分别35.16%和38.09%。查询干预进一步提示模型尚未可靠按编号查找。因此暂不执行上面的70M/2K GPU阶段，先在本机核对已有任务实现和训练监督。完整执行结果及保留的失败见`docs/far-recall-results-2026-09-14.md`。
