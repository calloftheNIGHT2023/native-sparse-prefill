# 混合精度与较长上下文成本试验：运行前协议

本轮是前一轮质量/成本小试后的独立测速，不延长训练，不使用报告窗口选参，不改变此前结果。

1. 模型为固定 Qwen2.5-0.5B base，底座和 rank8 LoRA 参数保持 FP32。比较 FP32 算术/BF16 注意力，与 BF16 autocast 混合精度；不是把所有参数直接转成 BF16。
2. 配置顺序：FP32 8K、混合精度 8K、混合精度 16K。每种配置内测稠密、FP32 池化 K4、FP32 池化 K16；全部使用通过前轮验证的同步补丁扩展，稠密路径实际调用 PyTorch Flash SDPA。
3. 每个配置执行两轮条件正序/反序；每个条件分别做 3 次预热、10 次同步墙钟测量。保存每次样本、GPU event 区间、峰值显存、开始和结束时间。
4. Prefill 使用全输入、创建全新 KV cache，只计算最后一个位置的 logits，不做 decode。前向/反向则计算全 token logits 和 FP32 交叉熵，包含清梯度，不执行优化器、不包含输入搬运和梯度有限性检查。它不能直接当成前轮完整训练步耗时。
5. 参数更新数固定为 0，初始和最终适配器 SHA 必须一致。输入只拼接前轮两个训练窗口，8K 使用同一前缀；人工接缝只用于成本测试，不报告语言质量。
6. 在各配置计时前，检查同精度下 256 token 的 native eager/自定义稠密，以及稠密/全块稀疏输出和 LoRA 梯度。沿用 logits 相对误差 <0.02 / <0.01、NLL 差 <0.05，并预设梯度相对 L2 <0.10。使用实际长度做未来 token 扰动的前缀不变检查。引用前轮 K16 参考测试与补丁反向重复测试；不把有限诊断称为完整正确性证明。
7. 每进程上限 360 秒；数值失败、OOM、超时或运行时错误保留后停止队列，不放宽门槛。没有仅靠测速自动扩大训练的逻辑。
8. 在相同精度和长度、同轮次内配对，若两个轮次时间比均不超过 0.95，仅说明该测量范围有值得继续核查的成本空间，不说明质量已恢复或方法有原创性。

机器可执行设置：`configs/flashmoba-mixed-cost-v0.json`。完整结果尚未生成。
