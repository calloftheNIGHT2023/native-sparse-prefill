# 16K/32K训练计算成本：长度与保留块数

用户明确接受以适度质量代价换取训练成本收益。已有16K结果中K32比密集更慢；已有32K结果只测了prefill，没有32K反向成本。因此补齐同一实现的长度边界，判断更长输入能否在保留更多块时仍省计算。此轮只提供成本证据，不产生质量结论。

使用既有密集适配种子0的256步断点，同一套Qwen2.5-0.5B LoRA权重、BF16计算、FP32主参数和池化、分块冻结输出头损失。保留原实现、环境、扩展与模型文件哈希核验；先重放4个校准窗口；所有权重前后摘要必须一致，0优化更新。

两轮输入分别由已有训练窗口0/1、2/3拼接，形成32769 token流；16K使用其嵌套前缀。拼接边界仅用于成本测试，不当成长文质量数据。每轮测16K/32K × K0/16/32，第二轮长度和K顺序均反向；每格2次热身、3次同步计时，共12格、36次计时、24次热身。

计时包括输入搬运、zero_grad、完整模型前向、所有token损失与反向、梯度裁剪。没有optimizer.step、训练断点保存、验证等环节，不称完整训练账单或推理加速。保留损失、梯度范数、峰值显存、输入哈希与UTC；只报告有限性，不把不同稀疏条件的损失当近似精度检验。

单作业上限360秒，若OOM/内核异常则保留日志并停止；不自动改精度、裁剪长度或丢弃慢样本。按两轮配对中位数报告，只有两个输入样本，不外推跨模型、设备或统计置信结论。当前质量曲线评测结束后串行运行，避免GPU争用。此轮不启动新训练或新题质量确认。
