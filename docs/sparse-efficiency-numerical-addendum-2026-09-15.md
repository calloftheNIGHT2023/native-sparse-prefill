# 实现迁移中的数值边界：后续诊断记录

本记录在 v0 冻结检查点重放失败之后写入，不能视为事前标准。

原定 FP32 输出分数容差 rtol=1e-4、atol=1e-4 未全部通过。原始失败目录和记录保持不变，不提高容差把它改成成功。

已定位的第一个噪声批次（从第64条开始）中：第一层两实现选点完全一致、输出最大差 8.94e-7；第二层输入差 2.65e-6，第73条的第132个查询交换了一个选中位置，原第6与第7名远程候选分数差约 1.19e-6。该批最终 logit 最大差 1.43，但答案仍逐个一致。相同第二层输入单独比较两实现，选点一致，输出差约 1.62e-6。因此这是实际观察到的有限精度误差经硬选择放大的个案，不能说所有差异都已解释。

后续做两个独立记录：

1. 完成全部 FP32 重放，原容差不变，记录每组输出差异与平均 NLL；即使答案全一致，也将状态标为 predictions_match_but_logits_differ，不能称数值等价已通过。
2. 两实现同时转 FP64 重放同一批冻结权重和已暴露题目，用于判断差异是否主要来自计算顺序和有限精度。FP64 结果不能代替 FP32 或 GPU 的验证。

两个记录均无参数优化，不产生新的泛化测试。原模型、原始预测和旧归档均保持。未来 CUDA 上还需按实际精度复核，不能因 CPU 的答案相同就承诺可直接继续原训练轨迹。

基准脚本 v0 另有诊断组件调用错误（samples(part()) 而非 samples(part)），导致只完成长度256部分。该错误与模型数值问题无关，已修正后另存 v1，原计时日志不改写。
